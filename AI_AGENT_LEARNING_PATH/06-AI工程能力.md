# 06｜AI 工程开发能力：掌握到能排障、扩展和上线

评价标准不是“看过语法”，而是你能否在本项目中独立完成需求、测试、排障和技术解释。

## 一、Python

### 1. 面向对象

**需要掌握**

- class、继承、组合、ABC、Protocol、dataclass、依赖注入。
- 知道何时用函数、何时用对象；接口应隐藏供应商细节。
- 能设计 `LLMService`、`EmbeddingService`、`VectorStore`、`Tool` 这类可替换深模块。

**项目证明**

- 解释 `LLMService` ABC 为什么让 Mock 和 OpenAI-compatible 可替换。
- 增加一个 provider 时业务 generator 无需修改。

**不要求**

- 为使用设计模式而制造复杂类层次。

### 2. 异步

**需要掌握**

- event loop、coroutine、await、I/O-bound 与 CPU-bound。
- 并发限制、timeout、cancel、异常传播；不要在 async 路由里执行阻塞 I/O。
- SQLAlchemy 同步 Session 与 async HTTP 混用时的边界。

**项目证明**

- `chat_json` 使用 `httpx.AsyncClient`。
- 能解释为什么 PDF 解析/大型 Excel/CPU-heavy rerank 不应直接阻塞事件循环。
- 能用 semaphore 限制并发模型调用。

### 3. FastAPI

**需要掌握**

- Router、Depends、middleware、exception handler、response model。
- 认证/授权依赖、请求状态、文件上传、流式/后台任务边界。
- OpenAPI、测试客户端、生命周期和健康检查。

**项目证明**

- 从 `/knowledge/ask` 跟到 `grounded_answer`。
- 为 Agent 新增 endpoint 时复用 principal、permission 和 service，不把业务逻辑写在路由里。

### 4. Pydantic

**需要掌握**

- BaseModel、Field、枚举、嵌套模型、validator、strict/extra=forbid。
- `model_validate`、`model_dump`、JSON Schema。
- API 输入、LLM 输出、Celery payload 三处都视为不可信边界。

**项目证明**

- 为 Prompt 输出和 Agent 工具定义 Schema。
- 能处理版本兼容、拒答和 ValidationError。

### 5. SQLAlchemy

**需要掌握**

- Declarative model、relationship、select、join、索引、唯一约束。
- Session 生命周期、flush/commit/rollback、事务和乐观锁。
- N+1、分页、批量写、连接池。

**项目证明**

- 解释为什么 `db.flush()` 可先获得 ID，而整体事务尚未提交。
- Agent 多步骤写操作用一个大事务还是短事务 + 状态机，能讲权衡。
- 防止跨项目查询漏加 scope。

## 二、工程组件

### 1. Docker

**需要掌握**

- Dockerfile 分层、镜像、容器、volume、network、healthcheck。
- Compose profiles、环境变量、非 root、secret 不进镜像。
- 能定位“代码问题、配置问题、网络问题、健康检查问题”。

**项目证明**

- 讲清 frontend/backend/PostgreSQL/Redis/Celery/Milvus 连接。
- 能重建单服务、看日志、执行迁移和 smoke test。

### 2. Redis

**需要掌握**

- cache 与 broker 的不同角色、TTL、key scope、序列化。
- 缓存击穿/穿透、过期一致性、租户污染。
- Redis 不是事实主库，不能用作最终审核状态唯一来源。

**项目证明**

- 解释 Redis 在 Celery broker/result backend 中的作用。
- 设计带 project/version/permission 的 RAG 缓存 key。

### 3. Celery

**需要掌握**

- broker、worker、task、result backend。
- 幂等、at-least-once、ack、retry/backoff、timeout、cancel。
- 长任务拆分、进度、部分成功、补偿和可观测性。

**项目证明**

- `CeleryTaskQueue` 用作用域化 idempotency key 去重。
- 能指出：消息重投可能导致重复执行，因此业务幂等不能只依赖 Celery task id。

### 4. PostgreSQL

**需要掌握**

- 表/索引/执行计划、事务隔离、锁、JSONB、FTS。
- 备份恢复、迁移、连接池、慢查询。
- RLS 和最小权限作为多租户纵深防御。

**项目证明**

- 为检索过滤和 audit 查询设计复合索引。
- 能分析 PostgreSQL 与向量库的职责边界。

### 5. Git

**需要掌握**

- branch、commit、merge/rebase、冲突、tag、bisect。
- 小步提交、PR、CI、review、回滚。
- 数据库迁移与代码版本协同。

**项目证明**

- 每个改造有测试、评测报告和清晰 commit。
- Prompt/Agent 配置也要有可追踪版本，不只代码进 Git。

## 三、掌握深度分级

| 能力 | 会用 | 能独立开发 | 高级岗位表达 |
|---|---|---|---|
| Python/FastAPI | 写接口 | 分层、异常、权限、测试 | 解释并发、边界、演进 |
| Pydantic | 定义字段 | 严格 LLM/工具契约 | Schema 版本与失败治理 |
| SQLAlchemy | CRUD | 事务、索引、性能 | 多租户、并发、一致性权衡 |
| Docker | 启动 Compose | 排障、健康检查、配置 | 部署拓扑和安全基线 |
| Redis/Celery | 发任务 | 幂等、重试、进度 | 语义、故障恢复、容量 |
| PostgreSQL | 建表查询 | 索引、迁移、备份 | RLS、锁、性能与治理 |
| Git/CI | 提交代码 | PR 和自动测试 | 发布、回滚、可审计变更 |

## 四、面试回答模板

> AI 应用工程不是只会调模型 API。我需要把模型放进一个可靠的软件系统：FastAPI 处理受控入口，Pydantic 定义不可信边界，SQLAlchemy/PostgreSQL 管理事务和审计，Redis/Celery 承载可重试的后台任务，Docker/CI 保证环境一致。我的掌握标准是能沿真实调用链开发、测试、排障，并解释幂等、权限、成本和失败恢复。

## 五、阶段作业

1. 给模型调用增加 timeout 分类、受控重试和 token usage。
2. 把一个耗时摄取/评测任务迁到 Celery，验证重复投递不产生重复结果。
3. 对混合检索查询做 `EXPLAIN`，记录索引前后变化。
4. 做一次故障演练：Redis 不可用、模型超时、向量库不可用，记录降级策略。
