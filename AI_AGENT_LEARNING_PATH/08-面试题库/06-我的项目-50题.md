# 我的项目 50 题

## 1. 用一句话介绍项目？
**答案：** 面向银行一表通字段的证据驱动业务口径与技术溯源AI辅助平台。  
**追问：** 主产物是什么？  
**高级回答：** 可审核、可引用、可导出的口径和技术溯源，不是聊天答案或自动生成SQL。

## 2. 项目解决什么痛点？
**答案：** 模板复杂、口径分散、场景差异、技术来源难追和变更影响难管理。  
**追问：** AI真正做什么？  
**高级回答：** 取证、推荐、草稿和缺口识别；最终采用、审核和UAT仍由人负责。

## 3. 项目业务主线是什么？
**答案：** 固定一表通字段→场景调研→业务口径/技术溯源→双层取数→交付。  
**追问：** 为什么不是先让AI生成？  
**高级回答：** 字段和场景是业务事实，先建领域模型才能约束AI边界。

## 4. 核心领域模型有哪些？
**答案：** TargetField、ProductScenario、ScenarioMapping、Source/Mart和双层Mapping。  
**追问：** 为什么双层？  
**高级回答：** Source→Mart与Mart→YBT责任和规则不同，拆开便于证据、审核和影响分析。

## 5. 为什么AI不生成可执行SQL？
**答案：** 平台目标是需求口径，任意SQL存在安全和正确性风险。  
**追问：** SQL有什么作用？  
**高级回答：** SQL解析和安全探查只提供血缘/证据，实际执行受SafeSqlExecutor约束。

## 6. Excel模板如何处理？
**答案：** 解析多层表头、合并单元格和动态场景，先预览再apply。  
**追问：** 为什么分预览/apply？  
**高级回答：** 防止错误解析直接污染正式模型，给用户确认映射的机会。

## 7. 知识库支持哪些文件？
**答案：** XLSX、DOCX、PDF、TXT、MD、SQL等。  
**追问：** 只存纯文本吗？  
**高级回答：** 转为保留Sheet/Cell/Page等出处的KnowledgeUnit，并带scope/version/classification。

## 8. RAG检索策略是什么？
**答案：** 结构化可见性过滤+加权关键词+向量+业务规则。  
**追问：** 是完整BM25吗？  
**高级回答：** 当前不是，是MVP关键词倒排；我会诚实说明并用RRF/BM25实验升级。

## 9. HybridRetriever 如何做权限？
**答案：** 只召回project/global/同机构scope且enabled的KnowledgeUnit。  
**追问：** 为什么还要citation校验？  
**高级回答：** 索引可能延迟/异常，返回前回查事实库形成纵深防御。

## 10. 当前rerank如何实现？
**答案：** 关键词、向量和字段/场景规则线性融合。  
**追问：** 是cross-encoder吗？  
**高级回答：** 不是；命名为rerank_score但本质规则融合，后续需独立精排实验。

## 11. 无检索结果怎么处理？
**答案：** 固定返回证据不足和补充知识的待确认问题。  
**追问：** 为什么不让模型常识回答？  
**高级回答：** 监管问题必须可追溯，参数知识无法作为项目证据。

## 12. Citation 如何生成？
**答案：** 从检索结果构造知识单元ID、文件、Sheet/Cell/Page和引用片段。  
**追问：** 如何防伪造？  
**高级回答：** `validate_citations` 回查存在、启用和项目可见性。

## 13. 如何检测模型虚构表字段？
**答案：** 检查回答中的限定标识符是否出现在证据中。  
**追问：** 这个规则完整吗？  
**高级回答：** 不完整，只是额外护栏；技术草稿还用CatalogColumn做结构化验证。

## 14. 技术溯源如何验证物理字段？
**答案：** `_physical_value_allowed` 查询项目CatalogColumn。  
**追问：** 当前字段已有值时呢？  
**高级回答：** 只允许模型输出与已有值一致，防止无证据改写。

## 15. 为什么区分ai_generated_content和final_content？
**答案：** 防止模型草稿覆盖人工事实。  
**追问：** 如何采用？  
**高级回答：** 显式adopt/编辑并进入审核，保留版本和责任人。

## 16. LLM网关如何设计？
**答案：** `LLMService` ABC + Mock/OpenAI-compatible实现 + factory。  
**追问：** 好处？  
**高级回答：** 业务不依赖供应商，CI可Mock，模型切换集中治理。

## 17. Prompt运行时做什么？
**答案：** 选择最新启用Prompt、ModelProfile和本地/外部策略。  
**追问：** Prompt缺失呢？  
**高级回答：** 使用安全默认Prompt，要求仅据证据、禁止虚构/SQL、缺证据待确认。

## 18. 敏感数据如何控制外发？
**答案：** 根据confidentiality和模型local_only阻断或脱敏。  
**追问：** 只控制生成够吗？  
**高级回答：** 不够，embedding、rerank、日志和工具结果也要执行同一分类策略。

## 19. ModelCallLog 记录什么？
**答案：** 项目、模型、检索、Prompt版本、输入哈希、摘要、状态和延迟。  
**追问：** 当前不足？  
**高级回答：** token_usage为空、参数和provider request id不足，成本/回放能力需补。

## 20. 为什么需要 RetrievalLog？
**答案：** 记录查询、策略、候选数量、结果ID和延迟。  
**追问：** 有什么价值？  
**高级回答：** 可区分召回失败与生成失败，并支持线上排障和离线回放。

## 21. RAG当前有哪些指标？
**答案：** Recall@5/10、MRR、source/table/field hit、citation、groundedness、关键词、延迟。  
**追问：** 哪个指标较粗？  
**高级回答：** groundedness当前近似为有citation且无unsupported，需升级到claim-level。

## 22. 为什么有MockVectorStore？
**答案：** 单测/CI无需Milvus即可验证契约和流程。  
**追问：** 能代表生产性能吗？  
**高级回答：** 不能；Milvus容量、索引、备份、过滤和延迟需独立验收。

## 23. PostgreSQL与Milvus如何分工？
**答案：** PostgreSQL存事实/权限/事务，Milvus存可重建向量索引。  
**追问：** 一致性怎么保证？  
**高级回答：** 事实先写、异步索引、状态/重试、检索返回前回查，支持全量重建。

## 24. 元数据目录有什么作用？
**答案：** 管理schema/table/column并支撑来源推荐和物理字段验证。  
**追问：** 不能直连怎么办？  
**高级回答：** 导入Excel数据字典，保留同一Catalog抽象。

## 25. 数据探查如何保证安全？
**答案：** 用户选定候选后用固定模板和SafeSqlExecutor，只读且限制。  
**追问：** 敏感字段呢？  
**高级回答：** 不取top values/原值范围，落库和返回前二次识别过滤。

## 26. Source字段推荐如何解释？
**答案：** 综合字段代码、名称、注释、历史、知识、SQL和人工证据评分。  
**追问：** 推荐会自动填最终值吗？  
**高级回答：** 不会，用户选择后才填技术草稿，仍非最终口径。

## 27. SQL血缘如何建模？
**答案：** ScriptFile/Version、LineageNode/Edge并关联字段/集市。  
**追问：** 无法解析怎么办？  
**高级回答：** 保留unresolved和人工入口，不把猜测边当事实。

## 28. 变更影响分析怎么联动口径？
**答案：** 比较脚本版本实体变化，沿节点找到相关mapping并绑定证据。  
**追问：** 高风险后？  
**高级回答：** 标记stale/needs_review、通知角色并启动lineage_change_review。

## 29. 为什么Git仓库要allowlist？
**答案：** 防止SSRF式访问或读取未授权本地路径。  
**追问：** Token怎么传？  
**高级回答：** 只通过环境变量注入子进程，不进URL、DB、payload或日志。

## 30. 权限架构是什么？
**答案：** Institution/Project membership、角色权限、统一resource guard。  
**追问：** 如何防body里的假project_id？  
**高级回答：** 加载实际资源并核对归属，PermissionService用Principal重新授权。

## 31. 审核流程如何设计？
**答案：** WorkflowDefinition/Instance、ReviewTask、Decision和快照。  
**追问：** 通过后做什么？  
**高级回答：** 固化版本、更新状态；血缘影响审核还会更新lineage_status。

## 32. UAT模块有什么价值？
**答案：** 管理套件、运行、finding、证据和签署。  
**追问：** AI评测能替代吗？  
**高级回答：** 不能，UAT验证业务流程和验收责任，AI评测验证质量组件。

## 33. 后台任务如何幂等？
**答案：** institution/project/job_type/idempotency_key哈希并查重。  
**追问：** 够吗？  
**高级回答：** 还需每个业务步骤和数据库唯一约束幂等，应对at-least-once重投。

## 34. Celery任务如何取消？
**答案：** queued可revoke不强杀，running状态需协作式检查。  
**追问：** 为什么不terminate？  
**高级回答：** 强杀可能留下半写状态；任务应在安全边界检查cancel并保存进度。

## 35. Observability当前有什么？
**答案：** request id、结构化HTTP日志、指标、限流和安全响应头。  
**追问：** Agent还缺什么？  
**高级回答：** 统一trace、tool span、token/cost、分布式关联和质量告警。

## 36. 项目的安全亮点？
**答案：** AI不自由连库、只读SQL、敏感外发控制、citation可见性、Git allowlist。  
**追问：** 还可加强？  
**高级回答：** PostgreSQL RLS、secret manager、工具注入测试、供应商策略和恢复演练。

## 37. Docker部署拓扑？
**答案：** 前端、FastAPI、PostgreSQL，production profile加Redis/Celery/S3，Milvus可选。  
**追问：** Compose等于生产就绪吗？  
**高级回答：** 不等于，还需HA、备份、secret、容量、监控和灾备验收。

## 38. 测试策略是什么？
**答案：** 大量后端pytest、前端build、迁移测试、smoke和性能基线。  
**追问：** Mock的局限？  
**高级回答：** 验证流程不验证真实模型/数据库/向量质量，需环境分层测试。

## 39. Smoke test为什么重要？
**答案：** 用合成文件走完整业务链验证关键约束。  
**追问：** 覆盖哪些AI边界？  
**高级回答：** 真实citation、无证据拒答、Recall/MRR、敏感保护、AI不覆盖人工口径。

## 40. 项目当前最大技术债？
**答案：** 严格结构化输出、token/cost、真正BM25/rerank和claim-level评测不足。  
**追问：** 先做哪个？  
**高级回答：** 先Schema/日志使行为可测，再建立黄金集，随后改检索并量化收益。

## 41. 你准备如何Agent化？
**答案：** 把知识、目录、血缘、问题和草稿服务封装成有限工具。  
**追问：** 外层流程呢？  
**高级回答：** 保留现有Workflow/HITL，Agent只做动态取证和缺口分析。

## 42. 字段Agent第一版为何不用Multi-Agent？
**答案：** 单Agent更易控制、评测和定位收益。  
**追问：** 何时拆？  
**高级回答：** 当业务/技术职责、权限或上下文确实形成瓶颈且实验证明收益。

## 43. 字段Agent的停止条件？
**答案：** 证据充分、需人工、权限/永久错误或预算耗尽。  
**追问：** 如何防循环？  
**高级回答：** 最大8步、重复工具指纹、无状态进展检测和Token/费用预算。

## 44. 字段Agent如何创建问题？
**答案：** 生成具体问题、owner role、reason、evidence和幂等键。  
**追问：** 写入需审批吗？  
**高级回答：** 创建待办是低风险受控写，可自动；关闭/确认答案需授权人。

## 45. Agent结果保存在哪里？
**答案：** 现有AI草稿字段、Question/ReviewTask和Trace/BackgroundJob。  
**追问：** 为什么不单建Agent数据库？  
**高级回答：** 避免业务状态、权限和审计分裂，Agent是现有域服务的编排者。

## 46. 如何评字段Agent？
**答案：** 任务成功、工具选择、证据覆盖、问题有用性、人工编辑、安全、成本。  
**追问：** 与单次RAG怎么比？  
**高级回答：** 在相同字段/场景集上比较质量、步骤、延迟和总成本，不能默认Agent更好。

## 47. 如何讲项目的技术难点？
**答案：** 精确字段与语义检索并存、物理事实验证、跨层证据治理。  
**追问：** 你的决策？  
**高级回答：** 混合检索、目录/血缘工具、草稿/最终分离和claim-citation审核闭环。

## 48. 如何讲项目业务价值？
**答案：** 缩短找证据/写草稿时间，提高一致性和变更可追踪。  
**追问：** 有数字吗？  
**高级回答：** 只报告真实测量的处理时长、Recall、一次通过率和人工修改量，不编造ROI。

## 49. 如果面试官说项目不是Agent怎么办？
**答案：** 当前主系统确实以受控Workflow和RAG为主，复杂Agent只是下一阶段。  
**追问：** 这会减分吗？  
**高级回答：** 诚实区分已实现与规划更专业；我能说明为什么银行先治理闭环再Agent化。

## 50. 项目最能证明你转型的是什么？
**答案：** 把ETL口径/血缘优势转成可治理的LLM、RAG、Agent和平台工程。  
**追问：** 不是简单CRUD吗？  
**高级回答：** 真实难点在证据、权限、模型不确定性、评测和审核联动，我能从源码与指标证明设计。
