# Agent 50 题

## 1. 什么是 Agent？
**答案：** 围绕目标观察状态、选择工具、执行动作并判断完成的系统。  
**追问：** 一次 LLM 调用算吗？  
**高级回答：** 通常不算；Agent还需状态、工具、循环、停止条件、错误恢复和审计。

## 2. Agent 与 Chatbot 区别？
**答案：** Chatbot 主要对话，Agent 能对外部系统采取受控动作。  
**追问：** 风险差异？  
**高级回答：** Agent 有行动后果，因此工具权限、幂等、预算和人工审批比聊天体验更关键。

## 3. Workflow 与 Agent 区别？
**答案：** Workflow 路径预定义，Agent 根据状态动态选择路径。  
**追问：** 银行项目选哪个？  
**高级回答：** 外层审核/UAT用 Workflow，动态取证局部用 Agent，形成确定外壳+弹性内核。

## 4. 什么时候不该用 Agent？
**答案：** 路径固定、规则明确、风险高且无需动态决策时。  
**追问：** 举例？  
**高级回答：** 审核状态流转、数据库迁移、正式交付发布应是确定性工作流。

## 5. Agent 的核心组件？
**答案：** 目标、状态、Planner、工具、Executor、Memory、验证器和停止条件。  
**追问：** 哪个是安全边界？  
**高级回答：** Executor和权限系统；Planner 可犯错但不能越过确定性执行边界。

## 6. Planner 做什么？
**答案：** 根据目标和状态选择下一动作。  
**追问：** 如何限制？  
**高级回答：** 输出有限 action enum、reason code和工具参数，不接受任意代码或自由 SQL。

## 7. Executor 做什么？
**答案：** 校验并执行工具，返回受控结果。  
**追问：** 为什么与 Planner 分开？  
**高级回答：** 把模型不确定决策与确定性权限、超时、幂等和审计分离。

## 8. 什么是 Tool Calling？
**答案：** 模型提出工具和参数，应用执行并把结果回传。  
**追问：** 如何防错误参数？  
**高级回答：** Pydantic strict Schema、服务端注入 scope、资源归属校验，失败返回结构化错误。

## 9. 如何设计好工具？
**答案：** 单一职责、参数最小、输出有限、可审计。  
**追问：** 工具越多越好吗？  
**高级回答：** 过多会增加选择错误；按业务能力聚合成深模块，并用工具选择评测优化。

## 10. 为什么不能给 Agent 任意 SQL 工具？
**答案：** 可能越权、泄漏、破坏数据或造成资源攻击。  
**追问：** 如何提供数据库能力？  
**高级回答：** 固定探查模板、只读账号、表列 allowlist、行数/超时限制和结果脱敏。

## 11. Agent State 应包含什么？
**答案：** 目标、步骤、证据、冲突、问题、草稿、预算和状态。  
**追问：** 是否保存完整推理？  
**高级回答：** 保存可审计决策摘要、工具结果 ID 和状态哈希，不依赖冗长私有推理。

## 12. 什么是 Working Memory？
**答案：** 当前任务的短期状态和中间结果。  
**追问：** 如何控制大小？  
**高级回答：** 结构化摘要、证据引用和去重，不把全量历史反复塞入上下文。

## 13. 什么是 Episodic Memory？
**答案：** 过去任务轨迹、结果和反馈。  
**追问：** 能直接复用吗？  
**高级回答：** 需按项目权限、版本和审核状态过滤；失败轨迹主要用于评测，不自动成为知识。

## 14. 什么是 Semantic Memory？
**答案：** 稳定的事实和知识库。  
**追问：** AI 草稿能进吗？  
**高级回答：** 只有审核通过的内容才提升权威等级，草稿必须与正式知识隔离。

## 15. Reflection 是什么？
**答案：** Agent 对结果进行检查并尝试修正。  
**追问：** 为什么可能有害？  
**高级回答：** 无限制反思会循环和增费；优先确定性验证，最多一次受限修正后转人工。

## 16. 什么是 ReAct？
**答案：** 交替进行推理和动作/观察的 Agent 模式。  
**追问：** 企业实现要注意什么？  
**高级回答：** 不保存私有长推理，动作必须结构化，循环有上限并记录可验证 reason code。

## 17. 什么是 Plan-and-Execute？
**答案：** 先生成计划，再由执行器逐步完成。  
**追问：** 计划会变化吗？  
**高级回答：** 工具结果与预期不符时可重规划，但受总步数、权限和目标不变约束。

## 18. 什么是 Agent Loop？
**答案：** 观察→决策→执行→更新状态的循环。  
**追问：** 如何防无限循环？  
**高级回答：** max_steps、重复工具指纹、状态无进展检测、时间/Token/费用预算和人工接管。

## 19. Agent 的停止条件？
**答案：** 目标达成、需人工、不可恢复错误或预算耗尽。  
**追问：** 模型说“完成”够吗？  
**高级回答：** 不够；应用检查证据、Schema、业务不变量和工作流入口条件。

## 20. 如何处理工具失败？
**答案：** 分类临时/永久错误，有限重试、降级或转人工。  
**追问：** 403 重试吗？  
**高级回答：** 不重试，记录越权并停止；网络/5xx可退避，但必须幂等。

## 21. 什么是工具幂等？
**答案：** 相同意图重复执行不会产生重复副作用。  
**追问：** 创建问题如何做？  
**高级回答：** 使用 project+field+scenario+question type 的 idempotency key 和数据库唯一约束。

## 22. Agent 如何做权限？
**答案：** 每次工具执行时根据当前 Principal重新鉴权。  
**追问：** 启动时检查一次不够吗？  
**高级回答：** 任务可能长、权限会变、模型参数不可信；scope必须由服务端派生。

## 23. Agent 如何防 Prompt Injection？
**答案：** 文档当数据、工具最小权限、参数和结果验证。  
**追问：** 如果 Planner被诱导？  
**高级回答：** Executor仍应阻断越权，安全不能依赖 Planner做对。

## 24. Agent 如何防数据外泄？
**答案：** 数据分级、模型路由、结果脱敏、网络 allowlist和日志治理。  
**追问：** Memory 呢？  
**高级回答：** Memory 同样按租户隔离、保留期限和敏感等级管理。

## 25. Human in the Loop 是什么？
**答案：** 在关键决策或不确定时由人审核、补证或批准。  
**追问：** 哪些步骤必须人工？  
**高级回答：** 冲突口径、未验证物理字段、高风险血缘变更、final_content采用和UAT签署。

## 26. 如何设计有用的待确认问题？
**答案：** 问题具体、指派角色、说明原因并绑定冲突证据。  
**追问：** “请确认口径”为什么差？  
**高级回答：** 不可执行；应指出哪个范围、哪两份证据冲突和确认后影响什么。

## 27. 什么是 Multi-Agent？
**答案：** 多个拥有不同职责/工具/上下文的 Agent 协作。  
**追问：** 为什么不一开始就用？  
**高级回答：** 增加通信、成本和归因复杂度；单 Agent可满足时先建立基线。

## 28. 何时拆 Multi-Agent？
**答案：** 职责、权限或上下文确实不同，且可并行并有量化收益。  
**追问：** 一表通怎么拆？  
**高级回答：** 可分业务证据、技术血缘、证据批判和草稿合成，但先验证单 Agent瓶颈。

## 29. Multi-Agent 如何避免互相幻觉？
**答案：** 共享结构化状态和证据 ID，不把自由文本互评当事实。  
**追问：** 谁决定最终结果？  
**高级回答：** 确定性验证器和人工流程，不能靠多数 Agent投票代替证据。

## 30. 什么是 Agent Orchestration？
**答案：** 管理 Agent 状态、步骤、工具、并发、错误和持久化。  
**追问：** 一定要用框架吗？  
**高级回答：** 不一定；先用显式状态机理解语义，复杂后再评估 LangGraph等框架。

## 31. 框架选型看什么？
**答案：** 状态持久化、可恢复、工具生态、观测、测试和锁定风险。  
**追问：** 不看什么？  
**高级回答：** 不以 Demo代码最短为核心，银行更关注可控性和可审计。

## 32. Agent 为什么适合异步任务？
**答案：** 多步工具和模型调用耗时且可能重试。  
**追问：** 如何实现？  
**高级回答：** BackgroundJob/Celery持久化状态，幂等步骤、进度、取消和断点恢复。

## 33. Agent Trace 应记录什么？
**答案：** 版本、步骤、决策、工具、结果摘要、耗时、预算和 outcome。  
**追问：** 保存原始数据吗？  
**高级回答：** 按敏感政策保存脱敏摘要/哈希和引用，密钥与原值不入 trace。

## 34. 如何回放 Agent？
**答案：** 固化输入状态和工具结果，用相同版本重跑决策。  
**追问：** 外部数据变了怎么办？  
**高级回答：** 使用不可变工具快照或 mock replay，区分“当时行为”与“当前重执行”。

## 35. Agent 如何评测？
**答案：** 评任务成功、工具选择、参数、轨迹、安全、成本和人工修改。  
**追问：** 最终答案正确够吗？  
**高级回答：** 不够，可能走了危险/高成本路径；轨迹和禁止动作也必须达标。

## 36. 什么是 Tool Selection Accuracy？
**答案：** Agent 在给定状态下选择正确工具的比例。  
**追问：** 只标一个正确工具吗？  
**高级回答：** 可定义允许集合和关键工具，避免过度约束等价轨迹。

## 37. 如何评价 Agent 轨迹？
**答案：** 检查必要证据、禁止动作、步骤效率和停止原因。  
**追问：** 必须与黄金轨迹完全一致吗？  
**高级回答：** 不必；多条合理路径可接受，但安全不变量和关键取证必须满足。

## 38. 如何控制 Agent 成本？
**答案：** 模型路由、步骤/工具/Token预算、缓存和早停。  
**追问：** 超预算怎么办？  
**高级回答：** 保存中间状态和证据，返回 needs_confirmation，不应继续赌一次模型调用。

## 39. 如何控制 Agent 延迟？
**答案：** 并行独立只读工具、动态路由、缓存、限制候选和异步化。  
**追问：** 哪些不能并行？  
**高级回答：** 有状态依赖或写副作用的步骤必须按序并保持版本检查。

## 40. Agent 写操作如何做并发控制？
**答案：** 幂等键、乐观锁/版本号、事务和冲突处理。  
**追问：** 保存草稿例子？  
**高级回答：** 带 expected_version；若人工已修改则拒绝覆盖并创建冲突任务。

## 41. 什么是 Agent 的“最小权限”？
**答案：** 每个工具只获得完成当前动作所需最小数据和操作。  
**追问：** 例子？  
**高级回答：** `get_lineage(field_id,max_depth)` 而非开放数据库连接或任意图查询。

## 42. 如何处理工具返回过大？
**答案：** 分页、上限、结构化摘要和按需展开。  
**追问：** 摘要会丢证据吗？  
**高级回答：** 摘要返回 ID 和定位，Agent可受控请求详情，最终 citation 指向原记录。

## 43. Agent 结果为何还需 Schema？
**答案：** 便于工作流消费、验证和版本兼容。  
**追问：** Tool Schema 与 Final Schema 区别？  
**高级回答：** 前者约束动作参数/结果，后者约束最终业务产物，二者均不替代语义校验。

## 44. Agent 如何处理证据冲突？
**答案：** 标记冲突、比较权威/时效/适用性并转人工。  
**追问：** 可以让 Reflection 决定吗？  
**高级回答：** 高风险监管冲突不能靠再想一次；Agent负责整理证据，不负责最终裁决。

## 45. 字段口径 Agent 的核心工具有哪些？
**答案：** 知识检索、字段详情、目录候选、血缘/影响、现有映射、创建问题、保存草稿。  
**追问：** 为什么没有任意 SQL？  
**高级回答：** 数据探查通过固定模板和 SafeSqlExecutor封装，保持只读、可审计。

## 46. 字段 Agent 如何判断证据充分？
**答案：** 综合可见性、权威、时效、适用性、直接性和一致性。  
**追问：** 相似度高就高置信吗？  
**高级回答：** 不行；高相似旧口径或外机构文档仍可能不可用，置信度由规则校准。

## 47. 字段 Agent 如何输出草稿？
**答案：** 分业务与技术 Schema，附 citation、冲突、问题和置信度。  
**追问：** 写 final_content吗？  
**高级回答：** 只写 AI 草稿，显式采用和审核后才进入最终值。

## 48. Agent 如何接入现有系统？
**答案：** 复用 service为工具，接入现有 Question、ReviewTask、BackgroundJob和日志。  
**追问：** 为什么不新建一套？  
**高级回答：** 避免权限、状态和审计分叉，Agent应是能力层而非影子平台。

## 49. 你的 Agent 设计最大权衡？
**答案：** 动态取证灵活性与银行可预测/可审计之间的平衡。  
**追问：** 具体怎么平衡？  
**高级回答：** Workflow外壳、有限动作Planner、确定Executor、硬验证器、预算和HITL。

## 50. 如何证明 Agent 比普通 Workflow 更好？
**答案：** 用同一任务集比较成功率、人工修改、步骤、成本和失败覆盖。  
**追问：** 如果没提升？  
**高级回答：** 保留确定性Workflow；Agent不是目标，业务质量和总成本才是。
