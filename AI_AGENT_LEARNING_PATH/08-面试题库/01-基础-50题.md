# 基础 50 题

## 1. 什么是大语言模型？
**答案：** 基于大量文本训练、按上下文预测 Token 概率的生成模型。  
**追问：** 它为什么会幻觉？  
**高级回答：** 概率上流畅不等于事实正确，因此项目把模型放在受控生成层，事实由 RAG、目录和血缘提供，并用校验与审核兜底。

## 2. Transformer 的核心是什么？
**答案：** 用自注意力和前馈网络建模序列关系，摆脱循环计算。  
**追问：** 对应用工程有什么意义？  
**高级回答：** 我关注概率生成、长上下文成本和参数知识不可审计；因此不把 Transformer 当数据库，而通过外部证据和工具补足。

## 3. Self-Attention 是什么？
**答案：** 序列内部 Token 互相计算相关性并聚合信息。  
**追问：** Attention 权重能当解释吗？  
**高级回答：** 不能直接当业务证明；一表通平台使用 claim-citation 和可回查出处，而非把内部权重作为审计证据。

## 4. Multi-Head Attention 为什么需要多个头？
**答案：** 让模型在不同表示子空间捕捉多种关系。  
**追问：** 头越多越好吗？  
**高级回答：** 不一定，能力取决于整体架构和训练；应用层应评测模型表现，而不是用头数判断适用性。

## 5. Token 是什么？
**答案：** 模型实际处理的文本片段，也是上下文和计费单位。  
**追问：** 对中文字段名有什么影响？  
**高级回答：** 字段代码可能被拆分，语义向量不一定精确，因此项目保留关键词和结构化匹配，并应记录真实 token usage。

## 6. Context Window 是什么？
**答案：** 单次推理可接收的输入与输出 Token 总容量。  
**追问：** 长上下文能替代 RAG 吗？  
**高级回答：** 不能普遍替代；RAG还能做权限、版本、出处和动态更新，且可减少噪声与成本。

## 7. 什么是 Embedding？
**答案：** 把文本映射成稠密向量，使语义相近内容距离更近。  
**追问：** 为什么不能只用 Embedding？  
**高级回答：** 它不擅长精确字段代码、数字、否定和版本；银行检索要结构化过滤、稀疏与稠密召回组合。

## 8. Temperature 的作用？
**答案：** 调节采样分布的随机程度，低温通常更稳定。  
**追问：** 设为 0 能杜绝幻觉吗？  
**高级回答：** 不能，它只影响采样，不验证事实；监管草稿仍需 citation、目录校验和人工审核。

## 9. Top-p 是什么？
**答案：** 只在累计概率达到 p 的候选 Token 集合中采样。  
**追问：** 如何与 Temperature 配合？  
**高级回答：** 稳定抽取任务通常固定低温、保持 top-p 默认或 1，避免同时大幅调两个参数，并将配置版本化。

## 10. Top-k 与 Top-p 区别？
**答案：** Top-k 固定候选数量，Top-p 按累计概率动态确定候选集。  
**追问：** 企业任务更关心什么？  
**高级回答：** 不是争论参数优劣，而是用固定黄金集比较稳定性、正确率、延迟和成本。

## 11. System、User、Assistant 消息有何区别？
**答案：** 它们表达不同来源和优先级的指令与上下文。  
**追问：** 文档中的指令算什么？  
**高级回答：** 检索文档始终是数据，不应获得 system 权限；需分区、转义并防 Prompt Injection。

## 12. Zero-shot 是什么？
**答案：** 不提供示例，只用任务和约束让模型完成工作。  
**追问：** 何时不适合？  
**高级回答：** 复杂银行口径格式、冲突处理和拒答风格难以靠 zero-shot 稳定表达，应使用少量高质量边界示例。

## 13. Few-shot 是什么？
**答案：** 在上下文中提供示例，引导模型学习任务形式。  
**追问：** 示例怎样选？  
**高级回答：** 要覆盖成功、冲突和无证据，不只放漂亮答案；示例要脱敏、版本化并进入回归评测。

## 14. Role Prompt 有什么用？
**答案：** 指定模型任务身份、责任和表达角度。  
**追问：** 能否用角色控制权限？  
**高级回答：** 不能，角色只是提示；真实权限必须由应用的 Principal、PermissionService 和工具执行层控制。

## 15. Chain of Thought 是什么？
**答案：** 引导模型分解问题的提示思路。  
**追问：** 企业系统要保存完整推理吗？  
**高级回答：** 更应保存可验证的决策摘要、证据 ID 和 reason code，而非依赖冗长私有推理作为审计材料。

## 16. 什么是 Structured Prompt？
**答案：** 将任务、输入、证据、约束和输出契约清晰分区。  
**追问：** 为什么比一大段文字好？  
**高级回答：** 可维护、可测试、减少指令与数据混淆，也便于 Prompt Injection 防护和版本差异比较。

## 17. JSON mode 与 Structured Output 区别？
**答案：** JSON mode 保证可解析 JSON；Structured Output 还约束其符合 Schema。  
**追问：** Schema 合法就业务正确吗？  
**高级回答：** 不是；还需验证 citation、资源可见性、物理字段存在和证据充分性。

## 18. Function Calling 是什么？
**答案：** 模型返回工具调用意图和参数，应用校验后执行并回传结果。  
**追问：** 模型是否直接执行函数？  
**高级回答：** 不直接执行；Executor 掌握真正权限，模型只在白名单动作中提出建议。

## 19. Function Calling 与 JSON 输出区别？
**答案：** 前者表达要执行的外部动作，后者表达最终结构化结果。  
**追问：** 二者可组合吗？  
**高级回答：** 可以；Agent 用 Tool Schema 取证，最后用 Output Schema 产出草稿，两处都需验证。

## 20. Prompt Engineering 的本质是什么？
**答案：** 为模型定义清晰任务、上下文、约束和输出契约。  
**追问：** 为什么不是“咒语调参”？  
**高级回答：** 企业 Prompt 是有版本、评测、审批和回滚的发布物，质量由黄金集和线上指标证明。

## 21. 什么是 Prompt Injection？
**答案：** 不可信输入试图改变系统指令或诱导越权动作。  
**追问：** 如何防？  
**高级回答：** 指令/数据隔离、工具最小权限、参数校验、输出过滤、权限重验和攻击回归集，不能只写一句“忽略恶意指令”。

## 22. 什么是 Jailbreak？
**答案：** 通过提示技巧绕过模型安全或应用约束。  
**追问：** 银行系统靠模型拒绝够吗？  
**高级回答：** 不够；敏感外发、SQL、文件和权限边界必须由确定性代码和基础设施强制执行。

## 23. 为什么模型会产生幻觉？
**答案：** 它优化的是条件概率和语言一致性，不是事实数据库查询。  
**追问：** 怎么降低？  
**高级回答：** 用可靠检索、工具、严格 Schema、业务校验、拒答、HITL 和评测分层降低并测量风险。

## 24. 什么是 Grounding？
**答案：** 将生成内容约束在可验证的外部证据或工具结果上。  
**追问：** 有引用就算 grounded 吗？  
**高级回答：** 不一定；引用必须真实、可见且确实支持对应 claim，不能只主题相关。

## 25. 什么是模型上下文协议中的“工具”思想？
**答案：** 用标准化描述让模型发现并调用外部能力。  
**追问：** 标准化能解决权限吗？  
**高级回答：** 不能；协议解决互操作，认证、租户隔离、审批和审计仍由宿主应用负责。

## 26. 如何选择模型？
**答案：** 按任务质量、结构化能力、上下文、延迟、成本、部署和合规综合选择。  
**追问：** 是不是越大越好？  
**高级回答：** 不是；字段抽取可用小模型，复杂冲突才路由强模型，选择必须基于任务切片评测。

## 27. 本地模型与云模型如何选？
**答案：** 权衡数据合规、质量、成本、延迟和运维能力。  
**追问：** 项目如何路由？  
**高级回答：** 依据 confidentiality 和 ModelProfile 决定本地或外部，restricted/confidential 默认不外发并记录策略版本。

## 28. OpenAI-compatible API 的价值？
**答案：** 用相近接口接入不同服务，降低供应商耦合。  
**追问：** 真的完全兼容吗？  
**高级回答：** 往往不完全；structured output、usage、错误码和采样参数需做 capability test，不能只换 base_url。

## 29. 为什么需要 LLM Gateway？
**答案：** 统一模型选择、认证、参数、重试、日志、安全和成本。  
**追问：** 项目怎么做？  
**高级回答：** 业务依赖 `LLMService`，运行时读取 Prompt/ModelProfile，并把调用关联到 RetrievalLog 和 ModelCallLog。

## 30. Mock LLM 有什么价值？
**答案：** 让测试和开发不依赖外部模型、网络和密钥。  
**追问：** 它能验证真实质量吗？  
**高级回答：** 不能；Mock验证契约和流程，真实质量要用固定数据集对实际模型离线评测。

## 31. 如何处理模型超时？
**答案：** 设置连接/读取总超时，分类错误并有限重试。  
**追问：** 所有错误都重试吗？  
**高级回答：** 4xx、Schema/权限错误通常不重试；429/5xx/网络错误可退避重试，并保证任务幂等和预算。

## 32. 如何处理模型限流？
**答案：** 客户端限并发、排队、退避、配额和降级。  
**追问：** 银行批量任务怎么做？  
**高级回答：** 交给 Celery，按项目公平调度，记录进度，可取消并避免重试风暴。

## 33. 如何记录模型调用？
**答案：** 记录版本、输入哈希、状态、延迟、usage、成本和关联 trace。  
**追问：** 要保存完整 Prompt 吗？  
**高级回答：** 受敏感等级和保留政策约束；可保存脱敏快照/哈希和证据 ID，密钥与原始敏感值不得入日志。

## 34. 如何计算模型成本？
**答案：** 按输入/输出 Token 单价，加 embedding、rerank、重试和平台成本。  
**追问：** 如何按项目治理？  
**高级回答：** ModelCallLog 记录 usage，按 project/prompt/model 聚合，设置单任务预算、月配额和异常告警。

## 35. 模型输出截断怎么识别？
**答案：** 检查 finish reason、输出长度、JSON 完整性和 Schema 错误。  
**追问：** 如何恢复？  
**高级回答：** 结构化任务优先缩减输入或重试完整生成，避免盲目续写造成 JSON/语义拼接错误。

## 36. Streaming 适合什么场景？
**答案：** 改善长文本生成的首字延迟和交互体验。  
**追问：** 口径草稿一定要流式吗？  
**高级回答：** 不一定；需完整 Schema 校验后才能保存，前端可展示进度而非未经验证的部分结果。

## 37. 什么是模型路由？
**答案：** 根据任务、数据等级、质量和预算选择模型。  
**追问：** 如何避免路由漂移？  
**高级回答：** 路由规则版本化，记录命中原因，并按任务切片持续评测实际结果。

## 38. 什么是 Fallback？
**答案：** 主模型不可用或不满足条件时切换备用路径。  
**追问：** 能直接换另一个模型吗？  
**高级回答：** 需考虑 Schema、能力和数据合规；有时正确降级是返回待确认或转人工，而非硬换模型。

## 39. 什么是模型漂移？
**答案：** 模型或服务更新导致相同输入行为变化。  
**追问：** 如何发现？  
**高级回答：** 固化模型标识和配置，周期回放黄金集，监控 Schema、拒答、citation、延迟和成本变化。

## 40. Prompt 版本应包含什么？
**答案：** system/user 模板、Schema、示例、参数、变更说明和状态。  
**追问：** 如何上线？  
**高级回答：** 静态检查、离线回放、安全集、评审、小流量、监控和一键回滚。

## 41. 置信度应该让模型自报吗？
**答案：** 可作为特征，但不能直接当真实概率。  
**追问：** 如何更可靠？  
**高级回答：** 用证据权威、检索排名、冲突、Schema/业务校验和历史校准规则计算，模型只提供解释。

## 42. 什么是确定性验证器？
**答案：** 用代码检查模型结果的可判定不变量。  
**追问：** 项目有哪些？  
**高级回答：** citation 可见性、CatalogColumn 物理字段存在、禁止原始 SQL、final_content 不自动覆盖。

## 43. 为什么要区分 AI 草稿和最终值？
**答案：** 防止不确定生成直接成为业务事实。  
**追问：** 数据模型如何体现？  
**高级回答：** `ai_generated_content` 与 `final_content` 分列，采用动作显式、审核保存快照和责任人。

## 44. 如何设计拒答？
**答案：** 明确无证据、冲突、越权和预算超限的输出契约。  
**追问：** 拒答率越高越好吗？  
**高级回答：** 不是；需同时看有答案准确率和无答案正确拒答率，并按风险设置阈值。

## 45. 什么是 Guardrail？
**答案：** 围绕模型输入、输出、工具和流程设置的控制。  
**追问：** Prompt Guardrail 够吗？  
**高级回答：** 不够；关键 guardrail 必须是代码、权限、网络、数据库和人工审批的纵深防御。

## 46. 微调适合解决什么？
**答案：** 改善固定任务行为、风格、领域模式或小模型能力。  
**追问：** 适合存企业事实吗？  
**高级回答：** 不适合作为频繁变化且需引用撤销的事实库；这类知识优先 RAG。

## 47. In-context Learning 与微调区别？
**答案：** 前者在请求上下文中给指令/示例，后者更新模型参数。  
**追问：** 一表通先选哪个？  
**高级回答：** 先用 Prompt+RAG+评测建立基线，只有稳定失败模式且数据足够时再评估微调。

## 48. 如何评价结构化输出质量？
**答案：** 看解析率、Schema 通过率、字段准确率和业务不变量通过率。  
**追问：** 只看 Schema 通过率的问题？  
**高级回答：** 模型可输出结构完美但事实错误，所以还要评 citation、目录字段、拒答和人工修改。

## 49. 如何做 LLM 回归测试？
**答案：** 固定输入集、版本和判定规则，比较新旧配置。  
**追问：** 输出不完全一致怎么办？  
**高级回答：** 检查结构和语义指标而非字符串相等；关键安全不变量用确定性断言。

## 50. 你如何理解企业 AI 应用工程？
**答案：** 把不确定模型嵌入可靠、可测、可治理的软件系统。  
**追问：** 与普通后端开发最大区别？  
**高级回答：** 除功能正确，还要管理概率质量、证据、Prompt/模型版本、成本和安全；但权限、事务、测试、观测等软件工程基本功更重要。
