# 00｜总学习地图

## 你的转型不是“从零开始”

你已有的能力与 AI 工程并非割裂：

| 既有 ETL 能力 | 转化后的 AI / Agent 能力 | 在一表通平台中的落点 |
|---|---|---|
| 数据口径分析 | Prompt 上下文建模、证据约束、评测标准设计 | 场景业务口径、技术溯源、待确认问题 |
| SQL / Shell | Tool 设计、只读执行、安全边界、血缘解析 | SafeSqlExecutor、SQL/Shell lineage |
| 数据仓库 | 企业知识建模、元数据目录、双层映射 | Source→Mart→YBT |
| 数据血缘 | Agent 证据图、变更影响分析 | LineageNode/Edge、ImpactAnalysis |
| 数据跑批 | Celery 作业、幂等、重试、可观测性 | BackgroundJob、worker、correlation id |
| 监管数据 | 高风险领域的拒答、审核、审计 | citation、HITL、UAT、AuditLog |

你的短板不是银行业务，而是要把已有经验翻译成 AI 工程语言，并补齐 LLM、RAG、Agent、评测和平台工程。

## 能力优先级

### P0：投递前必须掌握

- LLM 参数、结构化输出、失败处理。
- RAG 全链路及 Recall@K、MRR、citation、groundedness。
- FastAPI 请求链、Pydantic Schema、SQLAlchemy 事务。
- Agent 的工具白名单、状态、停止条件、人工审批。
- 银行权限隔离、敏感数据外发控制、审计追踪。
- 能讲清本项目的真实源码和至少一次量化改造。

### P1：面试高级岗位的重要加分项

- 混合检索、reranker、查询改写、元数据过滤。
- Prompt/模型/检索配置版本化与灰度发布。
- Celery 幂等、重试、死信/补偿和可观测性。
- Agent 离线/在线评测、回放和成本预算。
- SQL/Shell 血缘与变更影响联动人工流程。

### P2：第二个月以后深化

- 多 Agent、图编排框架、本地模型路由。
- PostgreSQL RLS、向量库容量与备份。
- 高级 reranker 训练、模型微调、复杂多跳检索。

## 项目总架构的面试版表达

> 我把一表通平台设计为证据驱动的 AI 工作流。监管模板、历史口径、数据目录和 SQL/Shell 血缘先转成带项目范围、敏感等级和出处定位的知识单元；检索层用结构化过滤、关键词和向量做混合召回；LLM 只能基于证据生成结构化草稿，物理表字段必须在目录中验证，无证据则产出待确认问题；草稿不会覆盖人工最终口径，后续经过多阶段审核、UAT、审计和离线评测。这个设计把模型的不确定性限制在可追踪、可拒绝、可人工接管的边界内。
