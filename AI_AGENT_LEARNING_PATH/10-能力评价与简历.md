# 10｜最终目标评价标准与简历包装

## 一、共同硬门槛

以下 8 项每项 0～3 分：

- 0：不知道；1：能解释；2：能在项目实现；3：能评测、排障并讲权衡。

| 能力 | 证据 |
|---|---|
| LLM 网关与结构化输出 | 严格 Schema、usage/cost、失败处理和测试 |
| Prompt 治理 | 版本、黄金集、发布门禁、回滚 |
| RAG | 解析、混合检索、citation、分层评测 |
| Agent | 工具、状态、停止条件、HITL、轨迹评测 |
| Python/API | FastAPI、Pydantic、异步、异常和测试 |
| 数据工程 | SQLAlchemy/PostgreSQL、事务、索引、血缘 |
| 平台工程 | Docker、Redis/Celery、CI、可观测性 |
| 银行治理 | 权限、隔离、敏感数据、审核、UAT、审计 |

总分 24：

- 0～11：继续项目训练，不急于投高级 AI 岗。
- 12～16：可投数据+AI、初中级 AI 应用工程师。
- 17～20：可重点投企业 AI 应用工程师。
- 21～24：具备 Agent 工程师面试竞争力，但仍看真实项目深度和系统设计能力。

任何总分都不能抵消两项红线：不会解释真实源码；没有评测数据却声称“效果显著”。

## 二、AI 应用工程师投递标准

### 可以投递

- 能实现并测试 OpenAI-compatible LLM 网关和严格结构化输出。
- 能独立完成文档解析、RAG、引用和离线评测。
- 能用 FastAPI/PostgreSQL/Celery/Docker 做可运行服务。
- 能解释超时、重试、权限、成本和降级。
- 至少一项改造有真实前后指标。

### 作品集最小集

- 平台架构图、RAG 时序图。
- 50 条黄金集与基线对比报告。
- Prompt/模型调用日志设计。
- 3 分钟演示视频或演示脚本。

## 三、Agent 工程师投递标准

在 AI 应用标准之上：

- 能讲清 Workflow、Agent 和 Multi-Agent 的选择。
- 有可运行 Agent 状态机，不只是框架 Demo。
- 工具每次鉴权、参数校验、幂等、超时和审计。
- 有停止条件、预算、失败恢复和人工接管。
- 有 20 条轨迹 + 20 条安全评测，unsafe action 为 0。
- 能解释为什么当前阶段用单 Agent，以及何时才拆多 Agent。

## 四、数据 + AI 工程师投递标准

这是你最快形成差异化的方向：

- 展示数据目录、数据口径、血缘和变更影响如何成为 Agent 工具。
- 展示 SQL/Shell 解析、只读探查和数据敏感保护。
- 展示 Source→Mart→YBT 的领域建模。
- 能把跑批经验翻译成幂等、重试、可恢复后台任务。
- 能讲元数据质量如何直接决定 RAG/Agent 质量。

## 五、简历定位

### 推荐标题

> 企业级 AI 应用开发工程师｜银行数据与监管科技背景｜RAG / Agent / FastAPI

不要把自己包装成“算法工程师”或“大模型训练专家”。你的竞争力是银行数据语义 + 企业 AI 工程 + 治理。

### 个人简介示例

> 银行保险行业数据开发工程师，具备数据仓库、ETL、SQL/Shell、监管报送、一表通、数据口径与血缘经验。围绕银行一表通场景设计并开发企业级 AI 辅助平台，覆盖 Excel/文档解析、项目级知识库、混合检索、证据化 RAG、OpenAI-compatible LLM 网关、Prompt/模型调用治理、SQL/Shell 血缘与变更影响、人工审核、UAT、权限和审计。目标岗位为企业 AI 应用 / Agent / 数据+AI 工程师。

## 六、项目名称与一句话

### 项目名称

**银行一表通业务口径 AI 辅助与证据治理平台**

### 一句话

> 面向监管报送字段的证据驱动 AI 平台，将监管模板、历史口径、元数据目录和 SQL/Shell 血缘转化为可引用知识，生成受控业务口径与技术溯源草稿，并通过权限、审核、UAT、审计和评测形成交付闭环。

## 七、简历项目 bullets

下面的数字占位符必须替换为真实结果，不能编造。

- 设计 OpenAI-compatible `LLMService` 网关与 Prompt/模型运行时配置，支持 Mock 与真实模型切换；记录 Prompt 版本、输入哈希、检索日志、延迟及 Token/成本，实现可回放调用链。
- 构建面向 XLSX/DOCX/PDF/SQL 的知识摄取链路，保留 Sheet/Cell/Page/Line 级出处，按机构、项目、场景、有效状态和敏感等级治理知识单元。
- 实现结构化过滤 + 关键词 + 向量的混合检索和 citation 校验；在 `[N]` 条黄金问题上将 Recall@5 从 `[A]` 提升至 `[B]`、MRR 从 `[C]` 提升至 `[D]`。
- 设计证据约束的业务口径与技术溯源生成：AI 仅写草稿，不覆盖人工最终值；物理 schema/table/field 必须经数据目录验证，无证据或冲突时自动生成待确认问题。
- 解析 SQL/Shell 脚本形成字段/表级血缘，并对脚本版本差异进行影响分析；高风险变更自动标记相关口径并触发技术审核工作流。
- 建设机构/项目级权限、敏感数据外发控制、五阶段审核、只追加审计、UAT 和可恢复后台任务，支持从请求、检索、模型到交付的追踪。
- 设计字段口径分析 Agent 原型，封装知识、目录、血缘和问题工具；通过步骤/Token 预算、重复调用检测、工具级鉴权和确定性验证控制自主行为，在 `[N]` 条轨迹/安全集上 unsafe action 为 0。

## 八、面试项目讲解结构

### 3 分钟

1. 业务问题：一表通字段多、口径分场景、证据分散、变更影响难追。
2. 架构：解析→混合检索→受控生成→引用校验→审核/UAT。
3. 两个难点：精确字段与语义检索并存；AI 不能越过证据和权限。
4. 结果：用真实指标说明召回、人工效率、拒答或质量变化。
5. 下一步：Agent 化只用于动态取证，外层治理保持确定性。

### 10 分钟

- 领域模型：TargetField、Scenario、Source→Mart→YBT。
- RAG：Chunk、索引、混合检索、citation、评测。
- LLM：Gateway、Prompt、Schema、ModelCallLog。
- Agent：工具、状态、HITL、安全与成本。
- 工程：FastAPI、PostgreSQL、Celery、Docker、observability。
- 复盘：当前局限和量化改造。

## 九、五个 STAR 故事

1. **口径复杂**：如何把同字段不同场景拆成领域模型。
2. **证据不可靠**：为什么从纯向量升级混合检索和 citation。
3. **AI 幻觉风险**：如何用目录校验、拒答和草稿/最终值分离。
4. **脚本变更**：如何从血缘差异触发影响审核。
5. **企业上线**：如何处理权限、敏感外发、后台任务和 UAT。

每个故事必须包括：情境、目标、你的决策、权衡、行动、真实结果、复盘。

## 十、避免的包装方式

- 不说“自主多 Agent 平台”，如果当前只是扩展点或原型。
- 不把加权关键词叫完整 BM25，不把规则融合叫 cross-encoder rerank。
- 不说“杜绝幻觉”；说具体控制和测量方式。
- 不用未测量的“准确率 99%”“效率提升 80%”。
- 不隐藏 ETL 背景；把它变成数据语义、可靠性和银行治理优势。

## 十一、何时开始投

满足以下条件即可边投边学：

- 评分达到 16+，且 RAG、工程、银行治理均不低于 2。
- 有一项真实指标改造、一个 Agent 原型、一次完整模拟面试。
- 能在不看稿的情况下讲清 10 个真实源码文件。
- 能诚实回答项目局限及下一步，不把路线图当已实现。
