## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| deliverable.generate identity to technical mapping write | Package authority alone must not grant technical.edit. |
| queued persisted user/project to generator | Frozen non-legacy Principal and checked Project cross into Context/model/write phases. |
| Context/model outcome to BackgroundJobItem | Failures must be bounded and isolated without content leaks or fallback retries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-06-01 | Elevation of privilege | direct/queued mapping compile | high | mitigate | Require technical.edit and pass its returned Project; block until deliverable.generate-only tests show zero builder/model/write. |
| T-10-06-02 | Tampering | legacy peer ORM compiler | high | mitigate | Remove both compiler modules and production references; real-path plus static tests prove sole Context seam. |
| T-10-06-03 | Spoofing | queued actor recovery | high | mitigate | Active persisted User only, explicitly non-legacy Principal, fresh post-model actor/permission validation. |
| T-10-06-04 | Tampering / Repudiation | stale or blocked queue item | high | mitigate | Reuse optimistic Project→task boundary, bounded reason codes, no success audit/draft and per-item commits. |
| T-10-06-05 | Information disclosure | compile response/job diagnostics | medium | mitigate | Preserve only compatibility fields and bounded codes; never return/store raw Context, prompt or evidence bodies. |
