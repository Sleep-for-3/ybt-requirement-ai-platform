## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API/service caller to builder | Untrusted project and target identifiers, mode, as_of, reporting label, and candidate limits enter orchestration. |
| builder to existing model queries | Collector SQL crosses into project, institution, mapping, lineage, evidence, historical, and knowledge rows. |
| knowledge retrieval to context | Retrieval results and RetrievalLog metadata cross into the bounded contract with confidentiality rules. |
| context output to downstream consumers | In-memory facts, candidates, conflicts, and questions are serialized without persistence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-03-01 | Information disclosure | all context collectors | high | mitigate | Add project predicates to every semantic/mapping/lineage query, validate Project.institution ownership, use PermissionService, and run identical-code cross-project/institution fixtures. |
| T-09-03-02 | Tampering / repudiation | builder authority/state normalization | high | mitigate | Consume the shared status policy, preserve authority separately from state, prevent rejected/deprecated/retrieved/AI promotion, and emit conflicts instead of silent winners. |
