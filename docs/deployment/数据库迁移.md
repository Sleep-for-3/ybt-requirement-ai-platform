# 数据库迁移说明

查看状态：

```bash
cd backend
alembic current
alembic heads
alembic history
```

升级前创建一致性备份并暂停写入型 Worker，然后执行：

```bash
alembic upgrade head
```

只有 `current` 与唯一 `head` 相同，`/health/ready` 和项目 deployment readiness 才能通过。CI 会验证从空库、上一 revision、降一级后再升级三条路径。

降级只应在变更说明明确支持、数据备份已验证且回滚窗口获批时执行。先在副本演练 `alembic downgrade -1`；不要对生产库盲目降级。

## 从本地 SQLite 一次性迁入 PostgreSQL

Windows 统一启停脚本会在首次 production 启动时自动执行。也可在已初始化且暂停写入的 PostgreSQL 上手工运行：

```powershell
$env:PGPASSFILE = "<仅运行账号可读的 pgpass 文件>"
$env:MIGRATION_DATABASE_URL = "postgresql+psycopg://<迁移管理员>@127.0.0.1:5432/<数据库>"
backend\.venv\Scripts\python.exe scripts\迁移SQLite到PostgreSQL.py `
  --source backend\local_main_test.db `
  --batch-size 2000 `
  --replace-target
```

迁移脚本按 SQLAlchemy 正式模型列出 102 张共享业务表，分批读取，但目标库的清空、复制和序列重置在同一个事务内提交。`--replace-target` 会清空目标业务表，只能在确认目标库可被 SQLite 快照替换时使用；生产切换前必须暂停 API/Worker 写入并完成备份。统一启停脚本只会自动迁移到本次启动刚创建的专用数据库；任何预先存在且缺少完整迁移标记的数据库都会停止并列出非种子业务表，且只在完整成功后写入本机迁移标记。
