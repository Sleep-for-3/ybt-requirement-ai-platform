# 环境变量说明

生产环境至少配置以下变量，凭据应由 Secret 管理系统注入，不写入镜像、Compose 文件或日志。

| 变量 | 生产要求 |
| --- | --- |
| `ENVIRONMENT` | `production` |
| `AUTH_MODE` | `required` |
| `APP_SECRET_KEY` | 非默认随机值 |
| `JWT_SECRET_KEY` | 至少 32 字符 |
| `DATABASE_URL` | PostgreSQL SQLAlchemy URL |
| `CORS_ORIGINS` | 明确的 HTTPS 前端源，禁止 `*` |
| `DEBUG` | `false` |
| `TRUST_PROXY_HEADERS` | 按实际代理拓扑明确设置 |
| `ACCESS_TOKEN_MINUTES` | 访问令牌寿命（分钟），默认 `15`。前端在受保护请求收到 401 时会用刷新令牌**静默续期并重放一次**，因此长耗时业务（真实模型单步可达数分钟）不会把用户踢回登录页；续期失败才清会话并跳转登录 |
| `REFRESH_TOKEN_DAYS` | 刷新令牌寿命（天），默认 `7`。每次续期都会轮换刷新令牌并立即吊销旧令牌；旧令牌再次使用会被拒绝并返回 401 |
| `STORAGE_PROVIDER` | `local` 或 `s3` |
| `STORAGE_DIR` | 本地存储目录，仅 local 使用 |
| `S3_BUCKET_NAME` | S3 模式必填 |
| `S3_ENDPOINT_URL` | MinIO 或兼容服务使用 |
| `TASK_QUEUE_PROVIDER` | 生产建议 `celery` |
| `REDIS_URL` | Celery 模式必填 |
| `CELERY_BROKER_URL` / `CELERY_RESULT_BACKEND` | Worker 使用 |
| `KNOWLEDGE_INGESTION_BATCH_SIZE` | 知识索引单批写入行数，默认 `200`，允许 `10` 至 `2000` |
| `VECTOR_STORE_PROVIDER` | `mock` 或 `milvus` |
| `MILVUS_URI` | Milvus 模式必填 |
| `LLM_PROVIDER` | `mock` 或部署支持的云端提供方 |
| `LLM_BASE_URL` / `LLM_MODEL` | 非 mock 模式必填：提供方地址与模型 ID |
| `LLM_API_KEY` | 非 mock 模式通过 Secret 注入 |
| `LLM_API_KEY_ENV_NAME` | 指向保存密钥的环境变量名 |
| `LLM_FALLBACK_MODELS` | 可选：逗号分隔的兜底模型链。主模型返回 404 或 `400 model_not_found` 时按顺序重放同一请求（不改变提示词与脱敏策略）；留空即关闭 |
| `LLM_FALLBACK_BASE_URL` | 可选：兜底模型使用的第二提供方地址（例如国产模型网关）；留空表示仍用主地址 |
| `LLM_FALLBACK_API_KEY_ENV_NAME` | 可选：兜底提供方的密钥环境变量名；留空表示复用主密钥 |
| `LLM_TIMEOUT_SECONDS` | 后台生成类的单次提供方往返预算（秒），默认 `60`，允许 `1` 至 `180`；真实提供方实测 11–123 s，建议生产设为 `120` |
| `LLM_INTERACTIVE_TIMEOUT_SECONDS` | 交互式调用的独立预算（秒），默认 `90`，允许 `1` 至 `180`。作用于同步接口 `/projects/{id}/knowledge/ask` 与 `/ai-runtime/test-chat`：预算耗尽时问答接口降级为「仅返回证据、结论待确认」，连接测试返回 503 并附带提供方诊断。必须小于反向代理/浏览器请求超时 |
| `EMBEDDING_PROVIDER` | `mock` 或兼容提供方 |
| `EMBEDDING_API_KEY_ENV_NAME` | 指向密钥环境变量名 |
| `MAX_UPLOAD_BYTES` | 1 KiB 至 500 MiB |
| `UAT_LOCAL_PACK_DIR` | 本地真实脱敏 UAT 材料目录；不得提交 Git |
| `HEALTH_DETAILS_PUBLIC` | 默认 `false` |

启动时 `Settings.validate_configuration()` 会输出 error/warning/info；任何 error 都会阻止应用启动，消息不含密钥值。

## 会话与令牌续期

- 访问令牌只用于业务请求；刷新令牌只用于 `POST /api/auth/refresh`，两者都由前端保存在 `sessionStorage`。
- 受保护请求返回 401 时，前端先调用刷新接口：成功则重放**一次**原请求，失败（无刷新令牌/已轮换/已过期）才清空会话并跳转 `/login`。`/auth/login` 与 `/auth/refresh` 自身的 401 原样返回，不参与续期。
- 并发 401 只触发一次续期，避免刷新令牌被连续轮换两次而互相失效（刷新令牌是单次有效）。
- 上线自检：把 `ACCESS_TOKEN_MINUTES` 临时压到 `1`，登录后执行一条超过 1 分钟的业务操作（例如知识问答或生成草稿）。预期结果是操作正常完成、浏览器不发生跳转，服务端日志出现 `POST /api/auth/refresh 200`。
