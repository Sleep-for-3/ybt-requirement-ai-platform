# 服务器配置说明（生产机 103.236.97.213）

本文说明生产机上“配置在哪里、每个变量管什么、改了以后怎么生效”。部署与回滚步骤见《服务器上线操作手册》。

## 1. 主机与访问

| 项目 | 值 |
| --- | --- |
| SSH | `ssh -p 42438 root@103.236.97.213` |
| 系统 | Ubuntu 22.04 LTS，Docker 29.1.3，Docker Compose v2.40 |
| 站点 | `http://57008897.xyz`（Nginx 反向代理，80 端口） |
| 规格 | 16 vCPU / 16 GB 内存 / 根分区 29 GB |
| 业务代码 | `/opt/ybt/source`（Docker Compose 项目名固定为 `source`） |
| 持久化数据 | `/data/ybt/*`（Milvus、MinIO、对象存储、Embedding 缓存）与 Docker named volume |

> Compose 项目名决定 named volume 的名字（`source_postgres_data`、`source_backend_storage` 等）。
> 部署目录名不能随意改，也不要执行 `docker compose down -v`。

## 2. 配置文件位置

| 文件 | 作用 |
| --- | --- |
| `/opt/ybt/source/.env` | **唯一配置来源**（权限 600，不进 Git）：编排变量 + 运行变量 + 密钥 |
| `/opt/ybt/source/docker-compose.yml` | 通用生产拓扑：迁移门禁、健康检查、依赖端口不对外 |
| `/opt/ybt/source/docker-compose.server.yml` | 本机差异：镜像标签、`/data/ybt` 路径、本地 Embedding |
| `/etc/nginx/sites-enabled/ybt.conf` | 反向代理；代理超时 600s |
| `/opt/ybt/source/backend/.env` | 历史遗留文件，新拓扑不再读取（内容已合并进根 `.env`） |

`.env` 的键合并规则：`backend/.env` 提供默认值，根 `.env` 优先，`--set` 最高。合并用
`scripts/deploy/merge-env-files.py`，它只打印键名、不打印值，避免密钥进入日志。

## 4. 常见配置变更怎么生效

| 变更内容 | 生效方式 |
| --- | --- |
| 普通变量（超时、开关、CORS） | `docker compose up -d backend worker beat` |
| `NEXT_PUBLIC_API_BASE_URL` | 必须重建前端镜像：`docker build -t ybt-frontend:<tag> --build-arg NEXT_PUBLIC_API_BASE_URL=… ./frontend`，再 `up -d frontend` |
| 镜像标签 `YBT_RELEASE_TAG` | `docker compose up -d`（回滚也用它） |
| Nginx 超时/域名 | 改 `/etc/nginx/sites-enabled/ybt.conf` 后 `nginx -t && systemctl reload nginx` |
| 密钥轮换 | 改 `.env` 后 `up -d backend worker beat`；数据库密码还要同步 `PRODUCTION_DATABASE_URL` 与 `POSTGRES_PASSWORD` |

## 5. 已知配置约束

1. **服务器出网受限**：`www.hejuapi.com` 解析到 Cloudflare，服务器访问超时（`Network is unreachable`）。
   已确认可达的国内模型入口：`api.deepseek.com`（返回 401，说明链路通）。接入国产模型时把
   `LLM_BASE_URL` 改成 `https://api.deepseek.com/v1`、`LLM_MODEL` 改成 `deepseek-chat`，
   并把对应密钥写入 `OPENAI_API_KEY`，然后重启后端与 Worker。
2. **代理超时**：`proxy_read_timeout` / `proxy_send_timeout` 必须 ≥ 600s，否则真实模型的长耗时生成会被 Nginx 截断成 504。
3. **端口**：PostgreSQL/Redis/Milvus 不发布到宿主机；只有 18000/13000 绑定 `127.0.0.1`。
4. **数据目录**：`/data/ybt/{milvus,milvus-minio,object-storage,fastembed-cache}` 是业务数据，不得删除；
   数据库、Redis、后端存储使用 named volume，同样不随发布重建。
