## 1. 服务器目录约定

| 路径 | 用途 | 说明 |
| --- | --- | --- |
| `/opt/ybt/source` | 运行中的业务代码 + `.env` + Compose 文件 | Compose 项目名 = `source`，决定 named volume 名字，**不要改名** |
| `/opt/ybt/releases/<tag>/` | 每次发布的源码包与解压副本 | 只做留档，不参与运行 |
| `/opt/ybt/backups/` | 数据库与配置备份 | `release-<tag>/` 由发布脚本创建；`source-before-<tag>/` 是源码与 `.env` 快照 |
| `/opt/ybt/logs/` | 发布日志 | 例如 `release-44c6af1.log` |
| `/data/ybt/` | 业务持久化数据 | `milvus`、`milvus-minio`、`object-storage`、`fastembed-cache`，**禁止删除** |

## 3. 发布一个新版本

### 3.1 本地（Windows 开发机）

```powershell
cd C:\Users\李儒伟\Documents\智能分析智能体平台
git status --short                      # 确认要发布的内容
python -m pytest -q                     # 后端全量回归（backend 目录，用 backend\.venv）
cd frontend; npm test; npx tsc --noEmit; npm run build; cd ..
git add <files>; git commit -m "..."
git push origin HEAD:main               # 发布基线以 main 为准
# 必须按 LF 导出：Windows 的 core.autocrlf=true 会把 .sh 写成 CRLF，
# 服务器上的 bash 会报 `$'\r': command not found`（2026-09-13 踩过）。
git -c core.autocrlf=false -c core.eol=lf archive --format=tar.gz `
  -o backend\.smoke-run\release\ybt-release-<tag>.tar.gz <sha>
(Get-FileHash backend\.smoke-run\release\ybt-release-<tag>.tar.gz -Algorithm SHA256).Hash.ToLower()
ssh -p 42438 root@103.236.97.210 "mkdir -p /opt/ybt/releases/<tag>"
scp -P 42438 backend\.smoke-run\release\ybt-release-<tag>.tar.gz root@103.236.97.210:/opt/ybt/releases/<tag>/
```

`<tag>` 建议用短 SHA（本次为 `0020b42`），它同时是镜像标签。仓库里的 `.gitattributes`
已把 `*.sh`/`Dockerfile` 固定为 `text eol=lf`，即使用普通 `git archive` 也不会再导出 CRLF。

### 3.2 服务器

```bash
cd /opt/ybt/source

# 1) 源码与配置备份（可回滚）
BK=/data/ybt/backups/source-before-<tag>; mkdir -p $BK
tar czf $BK/source.tar.gz -C /opt/ybt \
  --exclude='source/frontend/node_modules' --exclude='source/frontend/.next' \
  --exclude='source/backend/.venv' --exclude='*.pyc' source
cp -a /opt/ybt/source/.env $BK/dot-env.bak

# 2) 解包并把新代码同步进运行目录（保留 .env、node_modules、.next、数据目录）
mkdir -p /opt/ybt/releases/<tag>/src
tar xzf /opt/ybt/releases/<tag>/ybt-release-<tag>.tar.gz -C /opt/ybt/releases/<tag>/src
rsync -a --delete \
  --exclude '/.env' --exclude '/frontend/node_modules' --exclude '/frontend/.next' \
  --exclude '/frontend/.next-dev' --exclude '/backend/.env' --exclude '/backend/.venv' \
  --exclude '/backend/storage' \
  /opt/ybt/releases/<tag>/src/ /opt/ybt/source/

# 3) 合并 .env（新版本首次发布才需要；只打印键名，不打印密钥）
python3 scripts/deploy/merge-env-files.py --base backend/.env --override .env \
  --set COMPOSE_FILE=docker-compose.yml:docker-compose.server.yml \
  --set YBT_RELEASE_TAG=<tag> \
  --set BACKEND_HOST_PORT=18000 --set FRONTEND_HOST_PORT=13000 \
  --set PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
  --set NPM_REGISTRY=https://registry.npmmirror.com \
  --output .env.new
chmod 600 .env.new && cp -a .env .env.bak && mv .env.new .env

# 4) 校验编排（必须 exit 0，且镜像标签/端口正确）
docker compose config > /tmp/compose-config-<tag>.yml

# 5) 一键发布：备份数据库 → 构建不可变镜像 → 迁移 → 启动 → 健康门禁
nohup bash scripts/deploy/release-server.sh <tag> > /opt/ybt/logs/release-<tag>.log 2>&1 &
tail -f /opt/ybt/logs/release-<tag>.log
```

脚本会构建 `ybt-backend:<tag>` 与 `ybt-frontend:<tag>`，然后 `docker compose up -d`；
迁移由 `migrate` 一次性服务执行，API/Worker/Beat 必须等它成功才会启动。

### 3.3 验收（服务器端端到端）

```bash
cd /opt/ybt/source
grep -E '^YBT_RELEASE_TAG=' .env                      # 确认运行标签
docker compose ps --format '{{.Name}} {{.Status}} {{.Image}}'
curl -s http://127.0.0.1:18000/health/ready           # 必须 status=ready、各项 healthy

```

端到端冒烟统一在容器里跑（镜像自带 httpx 依赖，且和 backend 同处 `source_default` 网络）：

```bash
cd /opt/ybt/source
docker rm -f ybt-smoke >/dev/null 2>&1
mkdir -p /opt/ybt/logs/smoke-artifacts-<tag>
docker run --name ybt-smoke --network source_default \
  -v /opt/ybt/source/scripts:/scripts:ro \
  -v source_backend_storage:/app/storage \
  -v /opt/ybt/logs/smoke-artifacts-<tag>:/artifacts \
  -e PYTHONPATH=/scripts \
  -e SMOKE_BASE_URL=http://backend:8000/api \
  -e SMOKE_REUSE_EXISTING=1 \
  -e SMOKE_REQUEST_TIMEOUT_SECONDS=900 \
  -e SMOKE_ARTIFACT_DIR=/artifacts \
  -e SMOKE_FIXTURE_DIR=/app/storage/_acceptance \
  -e LLM_PROVIDER=openai_compatible \
  ybt-backend:<tag> python /scripts/smoke_test.py; echo "exit=$?"
```

* 只有退出码 `0` 才算通过；产物（正式交付包、UAT 报告/证据包、ready、health-details）落在
  `/opt/ybt/logs/smoke-artifacts-<tag>/`。
* `SMOKE_FIXTURE_DIR` 必须指向 backend/worker 也能读到的目录。这里复用 `backend_storage`
  卷（backend 与 worker 都挂在 `/app/storage`），否则元数据同步只会 `partially_completed`、
  catalog 检索必然找不到列。
* `SMOKE_REUSE_EXISTING=1` 复用生产库里既有的机构与验收账号，只新建一个带时间戳的项目。

脚本内部会强制校验的关键点（缺一即失败）：

1. 正式语义索引：`VECTOR_STORE_PROVIDER=milvus` 时先 `POST /projects/{id}/semantic-index/reindex`
   并等 job `completed`，再断言 `active_index_current=true` 与 Milvus 健康；
2. 元数据同步 `completed`、catalog 检索命中 `cert_type`、列画像产出空值率；
3. RAG 评测 `recall_at_5`、`mrr` 必须 > 0；知识问答必须有真实 citation；
4. UAT：8 个内置套件 / 94 条用例，首轮 `failed` → `retry_status=passed` 属于设计预期，
   finding 必须 `verified`、签核 4 份；
5. 交付包 12 个 sheet、跨机构访问 404、越权执行 403。

> 日志 `/opt/ybt/logs/smoke-0020b42.log`。

## 4. 回滚

按《发布与恢复Runbook》的判定入口执行，三种粒度：

1. **只回滚应用（推荐首选）**：把 `.env` 的 `YBT_RELEASE_TAG` 改回上一版标签，然后

   ```bash
   cd /opt/ybt/source && docker compose up -d
   ```

   数据库保持当前 revision；上一版镜像仍在本地（`docker images | grep ybt-`）。
   当前上一版为 `ede8472`（本次发布 `0020b42` 保留了它作为回滚目标，更早的 `44c6af1` 已清理）。
   只回滚应用层就够了：`0020b42` 与 `ede8472` 的数据库 revision 相同（`202609120027`），无需回滚数据。
2. **回滚源码与编排**：

   ```bash
   cd /opt/ybt/source
   BK=/data/ybt/backups/source-before-<tag>
   cp -a $BK/dot-env.bak .env
   rsync -a --delete --exclude '/.env' --exclude '/frontend/node_modules' --exclude '/frontend/.next' \
     --exclude '/backend/.env' --exclude '/backend/.venv' $BK/source/ ./
   docker compose up -d
   ```
3. **回滚数据（最后手段）**：`docker compose exec -T postgres pg_restore --clean --if-exists -U ybt -d ybt < $BK/db.dump`，
   或恢复到新库并按 Runbook 做只读核对后切配置。禁止 `docker compose down -v`。

回滚后必须核对：`alembic current` 与目标版本一致、业务行数不减少、登录/项目隔离/交付下载/UAT/健康检查五条最小路径可用。

## 5. 常见故障

| 现象 | 排查 | 处置 |
| --- | --- | --- |
| `health/ready` 返回 503 | `docker compose logs --tail=200 backend`；看 `llm_provider`、`vector_store`、`storage` 明细 | 依赖未就绪时等 `depends_on` 健康检查通过；配置错误按《服务器配置说明》修正 |
| 页面能打开但接口 401 循环 | `docker compose logs backend \| grep /auth/refresh` | 确认 `.env` 的 `ACCESS_TOKEN_MINUTES` 与 Nginx 超时；前端会自动续期 |
| 长耗时操作 504 | `grep proxy_read_timeout /etc/nginx/sites-enabled/ybt.conf` | 必须 ≥600s，改后 `nginx -t && systemctl reload nginx` |
| 模型调用失败 | `curl -sS -m 15 -o /dev/null -w '%{http_code}' $LLM_BASE_URL/...` | 服务器访问不了 hejuapi（Cloudflare），换成可达的国内模型并重启 backend/worker |
| 容器反复重启 | `docker compose ps` + `docker compose logs <svc>` | 先看 `migrate` 是否失败；迁移失败按 Runbook 处理，不要手工改 `alembic_version` |
| 磁盘不足 | `df -h /`、`docker system df` | 清理旧镜像 `docker image prune`（保留最近两版 `ybt-*`）；不要动 `/data/ybt` |
| 发布脚本报 `$'\r': command not found` | `file scripts/deploy/release-server.sh` 显示 CRLF | Windows `git archive` 导出了 CRLF：用 `git -c core.autocrlf=false -c core.eol=lf archive` 重新打包，或对已上传的脚本 `sed -i 's/\r$//'`；`.gitattributes` 已固定 `*.sh text eol=lf` |
| 元数据同步 `partially_completed`、catalog 检索 0 命中 | `docker compose logs worker \| tail -50` | 数据源文件不在 backend/worker 可见路径：验收时用 `-v source_backend_storage:/app/storage` + `SMOKE_FIXTURE_DIR=/app/storage/_acceptance` |
| 知识检索报 `No active formal semantic index` | `GET /api/projects/{id}/semantic-index/status` | Milvus 模式下必须先 `POST /api/projects/{id}/semantic-index/reindex` 并等 job 完成；接口现在返回 400（以前是 500） |
| 重复创建机构/用户返回 409 | — | 预期行为：端到端脚本复用既有资源时靠 409 判断“已存在”，不是故障 |
| 模型档案测试失败 `HEJU_API_KEY is not configured` | `select id,api_key_env_name,enabled from model_profiles;` | 档案引用的环境变量名和服务器 `.env` 不一致，见《服务器配置说明》§3.5 |
