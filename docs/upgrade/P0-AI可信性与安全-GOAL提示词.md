# P0 AI 可信性与安全修复 Goal 提示词

> 使用方式：将“Goal 目标”直接作为 Goal Mode 的目标；后续自动续跑或人工继续时，以本文件为唯一任务契约。每轮都必须先读当前进展，再继续未完成项，不得重复已完成工作，也不得只输出方案后停止。

## Goal 目标

在保留现有未提交修改、现有 API、现有数据、现有权限模型和现有业务路由的前提下，持续完成智能分析智能体平台 P0 级 AI 可信性、权限和证据修复。总目标完成前，不要因为一个阶段通过、上下文变长或局部测试成功而结束任务。每个阶段必须经历“核验现状 → 最小增量实现 → 定向测试 → 相关回归 → 前端类型/构建验证 → 浏览器验收 → 更新报告”，只有全部 P0 验收标准通过后才能标记目标完成。

## 开始

你是本项目的首席架构师、AI 应用专家、后端工程师、前端工程师、安全工程师和测试负责人。你的任务不是重新设计平台，也不是继续增加 AI 功能，而是先消除当前 AI 能力“看起来可用、实际不可信”的 P0 问题。

执行开始时必须读取并遵守：

1. 根目录及相关子目录的 `AGENTS.md`；
2. 本文件；
3. `docs/design/ai-skill-configuration-center-design.md`；
4. `docs/ai-runtime/模型调用流程.md`；
5. 相关模型、API、服务、前端页面、迁移和测试代码。

进入任何写操作前，第一条命令必须是：

```powershell
git status --short
```

必须保留工作区中已有用户修改。不得执行 `git reset --hard`、`git checkout --`、`git clean`、批量格式化、提交、推送或部署。不得读取或输出 `.env`、数据库密码、API Key、JWT、SSH 凭据。需要验证 Provider 时只使用现有安全配置机制和脱敏状态信息。

## 一、执行模式

### 1.0 当前执行快照

- P0-1 已通过权限与租户隔离验证。
- P0-2 至 P0-6 已完成增量实现、定向验证、前端测试、类型检查、隔离生产构建和浏览器业务验收。
- `202609200040`、`202609200041` 迁移必须支持旧库增量执行，也必须支持空库完整执行；只允许添加缺失列、索引和外键，重复执行不得报 duplicate column。
- 当前已通过 SQLite 和任务专用 PostgreSQL 16 隔离库的 `upgrade head -> downgrade -1 -> upgrade head -> current`；临时数据库和容器已清理。
- Mock Provider、Mock 路由和真实 API 传输浏览器验收均已通过，`pageErrors=[]`；其中真实 API 路径仍使用 Mock Provider，不得声明真实模型验收通过。
- 真实模型 Provider 是唯一未验证项。只有具备安全凭据并明确授权后才执行；不得把 Mock 成功写成真实模型成功。

### 1.1 Goal Mode 持续协议

每轮续跑严格执行：

1. 读取 `docs/handoff/ai-p0-remediation-goal-report.md`；
2. 检查 `git status --short`；
3. 选择一个尚未完成且没有前置阻塞的 P0 项；
4. 先核验该项当前真实实现，不把历史报告直接视为完成；
5. 只修改完成该项所需的最小文件范围；
6. 先跑定向测试，再跑相关回归、类型检查和隔离构建；
7. 需要界面行为时完成浏览器验收并保存截图或结果文件；
8. 更新报告中的状态、证据、失败和遗留项；
9. 如果总目标未完成且没有真实阻塞，继续下一项。
10. 涉及迁移的每轮修改后，必须执行隔离空库完整升级，以及至少一次回退再升级；未通过时不得进入浏览器或部署阶段。

不得在以下情况停止：

- 只是完成了现状分析；
- 只写了一份计划；
- 只修改了后端但验收还要求前端；
- 定向测试通过但相关回归未执行；
- 浏览器验收仍未完成；
- 还有可执行的 P0 项。

只有遇到无法从代码判断的重大业务选择、需要生产凭据、可能破坏用户数据或同一阻塞连续出现且无法绕过时，才向用户报告阻塞。

- 本轮任务不启动子代理。

- 不并行修改同一功能链路。
- 不做与本任务无关的重构。
- 不覆盖用户已有未提交修改。

## 二、P0 问题清单

### P0-1：AI 相关接口权限和租户隔离不完整

#### 问题

部分 AI、Prompt、评测和反馈接口缺少显式登录主体、项目权限或机构隔离。至少包括：

- `GET /prompt-versions`
- 评测案例创建和查询
- 评测运行和结果查询
- `POST /projects/{project_id}/feedback`

#### 目标

1. 所有相关接口必须有 `CurrentPrincipal` 或等价认证依赖。
2. 必须使用 `PermissionService` 校验项目或机构权限。
3. 记录 `created_by`、`project_id`、`institution_id` 时必须从认证主体和已授权项目推导，不能信任客户端任意传入。
4. 跨项目、跨机构和未登录访问必须返回 401 或 403，不得泄露资源是否存在。
5. 不破坏已有管理员只读语义，但“可读”必须建立在真实认证之上。

#### 必须测试

- 未登录请求被拒绝；
- 普通用户不能访问其他项目 Prompt、评测和反馈；
- 本机构被授权用户可以访问；
- 平台管理员权限按现有规则工作；
- 旧接口字段和响应结构保持兼容。

### P0-2：Mock、真实模型和规则结果可能被混淆

#### 问题

平台默认 Provider 可以是 `mock`，业务页面又没有统一展示当前结果是真实模型、Mock 还是纯规则算法。用户可能把固定模板文本当成真实 AI 结果。

#### 目标

1. 建立统一运行元数据 DTO，至少包含：

```json
{
  "execution_kind": "real_model | mock_model | deterministic | degraded",
  "provider": "mock | local | cloud",
  "model_name": null,
  "model_profile_id": null,
  "prompt_key": null,
  "prompt_version": null,
  "skill_key": null,
  "skill_version": null,
  "context_hash": null
}
```

2. 所有 AI 结果接口返回该元数据，不要求所有页面一次完成，但至少覆盖血缘解释、需求候选、场景草稿、双层 Mapping、监管问答和数据字段问答。
3. 前端统一显示“真实模型”“Mock 流程”“规则算法”“模型降级”，不得仅显示“AI”。
4. Mock 结果必须持续显示明显提示，不能只在管理员页可见。
5. 生产环境使用 Mock 时必须有启动健康检查、显眼告警或阻断策略，具体策略按现有环境配置机制实现。
6. 模型调用失败降级后必须保留确定性事实，并明确标注未调用真实模型。

#### 必须测试

- Mock、真实 Provider 和降级三种分支；
- 业务 API 返回正确 `execution_kind`；
- 页面展示正确标签；
- 模型不可用时确定性结果仍可用；
- 不把 Mock 成功声明为真实模型验收通过。

### P0-3：Prompt 版本配置目前存在错误承诺

#### 问题

Prompt 页面目前只显示原始 JSON，不能编辑、测试、差异比较、发布或回滚。同时通用运行时并未统一使用 `user_prompt_template` 渲染业务输入。

#### P0 目标

在完整 AI Skill 配置中心实施前，先消除错误承诺，二选一：

方案 A，推荐：

1. 建立统一、受控的 Prompt 渲染入口；
2. 只允许白名单变量；
3. 所有业务生成服务通过统一入口编译输入；
4. 发布版本必须固定，未知版本不得运行时即时拼装；
5. 页面明确显示“只读”或“可编辑”的真实能力。

方案 B，最小修复：

1. 明确标记当前 Prompt 页面为只读技术记录；
2. 删除会造成“修改后会立即影响生成”的错误提示；
3. 后端明确记录模板尚未参与运行时，防止后续误用；
4. 为 AI Skill 配置中心保留升级入口。

不得把一个实际未生效的字段继续展示成可配置能力。

#### 必须测试

- 模板变量白名单；
- 禁止任意表达式、代码和未声明变量；
- 模板版本固定；
- 旧 Prompt 调用兼容；
- 页面文案与实际行为一致；
- 未授权用户不能查看或修改。

### P0-4：伪 AI 标签必须纠正

#### 问题

部分功能只做规则聚合或状态标记，却在界面显示为 AI。

至少检查：

- 需求工作台“为什么这样判断？”；
- 质量规则的“AI 建议”状态；
- 来源推荐及其未实现的解释 Prompt；
- 任何没有模型运行元数据却显示“AI 生成”的页面。

#### 目标

1. 纯规则结果显示“规则判断”“证据汇总”或“待确认建议”。
2. 只有收到 `execution_kind=real_model` 或 `mock_model` 的结果，才能显示 AI 生成标识。
3. `ai_suggested` 如果作为历史领域状态保留，页面必须说明其来源；不能默认等同于真实模型生成。
4. 未调用的 Prompt key 和输出 Schema 必须标记废弃或接入，不能长期作为死代码。
5. 文本、颜色和帮助信息要能区分“事实、规则、AI 解释、人工确认”。

#### 必须测试

- 纯规则页面不再显示 AI；
- 真实或 Mock 模型页面显示对应标签；
- 历史 `ai_suggested` 数据仍可读取；
- 旧的领域状态和 API 不被破坏。

### P0-5：静默截断和证据丢失必须改为显式降级

#### 问题

部分生成上下文达到固定长度后会直接截断。部分模型输出 Schema 有 `citations`，但业务服务持久化时没有保存引用，导致页面无法证明模型结论。

#### 目标

1. 所有模型输入装配必须返回预算使用量、截断标志和缺口。
2. 不得在截断后继续把结果当作完整、可信草稿。
3. 超预算时优先选择：

```text
缩小范围 -> 明确阻断 -> 用户提高预算
```

不得静默删除后半段事实。

4. 模型声明的引用、被拒声明和校验结果必须可追溯，至少保存到现有审计 JSON、运行记录或新增的向后兼容可空字段。
5. 业务页面必须显示“上下文完整”或“上下文被截断，结论不完整”。
6. 引用不得指向本次输入范围外的对象。

#### 必须测试

- 未超预算正常生成；
- 刚好达到预算边界；
- 超预算阻断或明确降级；
- 截断标志可见；
- 合法引用保存并可查看；
- 非法引用被拒绝；
- 旧记录仍可读取。

### P0-6：AI 反馈和评测必须真正进入回归闭环

#### 问题

反馈目前只覆盖部分页面，评测主要是 RAG。AI 结果无法统一关联 Skill、Prompt 版本、模型、上下文和测试集。

#### P0 最小目标

1. 反馈必须包含认证用户、项目、目标类型、目标 ID、运行 ID或输出哈希。
2. 反馈可以关联 Mock、真实模型、规则结果和降级结果。
3. 管理员或授权评测员可以把反馈转为测试用例。
4. 现有 RAG 评测保持兼容，不要求本阶段立即完成所有 Skill 评测。
5. 至少为血缘解释、需求候选和 Mapping 草稿建立结构化回归样例或断言。

#### 必须测试

- 跨项目反馈被拒绝；
- 反馈关联到正确运行；
- 反馈可转为回归样例；
- 人工结论不被反馈或重生成覆盖；
- Mock、真实模型和规则结果不会混入同一统计口径而不标识。

## 三、实施顺序

### 阶段 A：基线和安全冻结

1. 建立 P0 报告；
2. 盘点所有 AI 相关路由和前端调用；
3. 先修复 P0-1；
4. 运行权限和租户隔离测试。

### 阶段 B：运行语义修复

1. 实现统一运行元数据；
2. 先接入血缘解释和一个生成任务；
3. 再接入其余 AI 接口；
4. 完成 P0-2。

### 阶段 C：配置与文案真实性

1. 按方案 A 或 B 修复 Prompt 语义；
2. 修正所有伪 AI 标签；
3. 完成 P0-3、P0-4 的浏览器验收。

### 阶段 D：证据完整性

1. 处理静默截断；
2. 保存引用和拒绝原因；
3. 修订页面状态；
4. 完成 P0-5。

### 阶段 E：反馈和评测

1. 修复反馈权限；
2. 关联运行信息；
3. 增加最小回归集；
4. 完成 P0-6。

### 阶段 F：全量验收

1. 定向后端测试；
2. 相关后端回归；
3. 前端相关测试；
4. TypeScript 和隔离构建；
5. 浏览器端到端验收；
6. 最终 `git status --short` 和 diff 检查；
7. 更新报告并确认没有凭据、数据库文件、构建产物和无关格式化。

## 四、不可违背的约束

1. 不创建第二套 AI、Prompt、评测、权限或日志平台。
2. 不把 Prompt 编辑、模型选择或测试结果做成无权限的公共接口。
3. 不允许用户配置任意代码、SQL、Shell 或模板表达式。
4. 不允许模型覆盖人工最终内容、正式口径、审核状态或固定交付。
5. 不读取或输出任何凭据。
6. 不连接生产环境做写操作。
7. 不使用生产数据库初始化脚本覆盖已有数据。
8. 测试必须使用隔离数据库、隔离账号和隔离目录。
9. 迁移必须向后兼容，旧数据、旧 API 和旧路由保持可用。
10. 迁移必须对已有列、索引和外键做存在性检测；不得假设旧库缺失声明字段或空库状态完全一致。
11. 使用隔离构建目录，不覆盖用户正在使用的 `.next`。
12. 启动服务前核对端口和进程；只停止本任务启动的服务。
13. 不提交、不推送、不部署，除非用户明确另行授权。

## 五、P0 完成定义

只有同时满足以下条件，才可以把 Goal 标记为完成：

1. P0-1 到 P0-6 全部状态为 verified；
2. 没有未授权 AI 接口；
3. Mock、真实模型、规则和降级在 API 与业务页面可区分；
4. Prompt 页面不再承诺未生效能力；
5. 伪 AI 标签已纠正或接入真实模型；
6. 不再静默截断模型上下文；
7. 模型引用和拒绝原因可追溯；
8. 反馈能进入回归闭环；
9. 定向测试、相关回归、类型检查和隔离构建通过；
10. SQLite 隔离空库迁移和回退通过，PostgreSQL 迁移在隔离环境通过；
11. 浏览器完成真实业务验收；
12. 报告明确列出已验证、未验证和遗留项；
13. 最终 diff 不包含凭据、数据库文件、构建产物或无关修改。

如果真实模型不可用，必须分别报告确定性、Mock 和真实模型验收状态。不得把 Mock 成功写成真实模型成功。
