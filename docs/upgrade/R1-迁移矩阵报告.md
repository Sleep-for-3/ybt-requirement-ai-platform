## 本轮复跑（2026-09-12，Windows 原生栈）

演练宿主机（WSL 发行版）在演练期间反复整体重启，容器内的 PostgreSQL 16 无法在单个窗口内完成迁移矩阵。为取得稳定证据，本轮改用**Windows 原生 Python 栈 + 本机 PostgreSQL 18.4 独立实例**（`127.0.0.1:15433`，数据目录位于 `backend/.smoke-run/pgdata`，不接触应用数据）复跑同一脚本：

* 6 个步骤全部 `exit=0`，`head=202609120027`，118 张表，ORM 契约问题 0；
* 4 个 `head` 状态的结构指纹与 PostgreSQL 16 容器运行结果**完全一致**：`c58431fba9aa6accccccb95bf91285480f2fdfd825cf8ebaf9269db9a22345ce`。

结论：迁移链与结构指纹不依赖宿主平台与 PostgreSQL 16/18 次版本差异。由于生产基线是 PostgreSQL 16，发布前仍须按 P0-6 在**脱敏生产副本（PostgreSQL 16）**上回放一次 `alembic upgrade head` 并比对同一指纹。
