## 3. 防偏移的持久化结构

第一次业务代码修改前创建或维护以下文件；已存在时增量更新，不重建清空：

- docs/development/long-run/GOAL-LOCK.md：固定总目标、约束、需求编号、阶段依赖、发布门槛、部署边界和目标版本。
- docs/development/long-run/GOALS.json：机器可读取的逐项状态和证据索引。
- docs/development/long-run/CURRENT-CHECKPOINT.md：当前唯一恢复入口。
- docs/development/long-run/NEXT-TASK.md：下一动作、原因、命令、预期产物及验收条件。
- docs/development/long-run/FAILURES.md：只追加失败与关闭事件。
- docs/development/long-run/DECISIONS.md：有依据的决策、被否决方案及用户目标变更记录。
- docs/development/long-run/BUDGET.json：整项任务的累计模型调用、token 及剩余额度。
- docs/development/long-run/rounds/ROUND-YYYYMMDD-NN.md：每一主要回合的交付。
- docs/development/long-run/evidence/：脱敏指标、命令摘要、公开可交付证据索引。

需求编号固定为：
- G-P0-A、G-P0-B、G-P0-C
- G-P1-A、G-P1-B、G-P1-C
- G-P2-CHUNK、G-P2-EMBED、G-P2-INDEX
- G-UX-AUDIT、G-UX-IMPLEMENT、G-UX-ACCEPT
- G-REMOTE-INVENTORY、G-REMOTE-BACKUP、G-REMOTE-DEPLOY、G-REMOTE-ACCEPT、G-REMOTE-ROLLBACK
- G-FINAL-DELIVERY

允许增加子项，不得删除、合并吞掉或擅自缩小原需求。状态只能使用 pending、in_progress、verified、blocked_external、awaiting_business。
每项至少记录 id、目标、依赖、状态、明确验收条件、证据等级、证据路径、代码身份、数据/索引/模型/Prompt/配置指纹、未关闭问题和下一动作。
技术状态、业务批准状态、实验启用状态分列记录，不能用一个“完成”字段混淆三者。

CURRENT-CHECKPOINT 必须含：
- 更新时间、目标版本、当前阶段、活动需求 ID、本轮唯一行为目标。
- 分支/HEAD、工作区关键差异、包含未跟踪源码的实际文件清单及 SHA-256。
- 已完成事项、修改文件、命令及退出码、通过/失败/未测数量。
- 当前进程、端口、WSL/Docker 服务、前后端访问地址和代码是否已加载。
- 本轮与累计真实模型调用数、token、预算、错误和重试数。
- 活动失败、外部阻塞、下一阶段是否允许进入及理由。
- 下一步唯一推荐动作、可执行恢复命令、预期结果和回退方法。
- 最后完整写入的 round_id、证据目录；不能留下半写入状态冒充检查点。

每轮开始、上下文压缩后、任务恢复后：
1. 读取 GOAL-LOCK → GOALS.json → CURRENT-CHECKPOINT → NEXT-TASK → 最近失败事件。
2. 简述总目标、当前阶段、本轮唯一目标。
3. 只读核对 Git、文件哈希、运行进程和未完成命令。
4. 如摘要与证据冲突，保留总目标，以实际代码及测试证据纠正状态，记录纠正原因。
5. 接续未完成动作，不重跑已经有效通过的昂贵整批评测。

每完成一个可验证里程碑立即更新台账；最长每 30 分钟保存一次；预见压缩时提前保存。
不能保证预知压缩，因此不能只依赖“压缩前提醒”。修改重要行为、启动付费测试、数据库迁移、部署切换前，均先落盘当前意图与回退。
突然中断后，下一轮识别 running、partial、orphaned 产物；保留半成品和首轮失败，明确续跑或另建 attempt，禁止覆盖成功身份。

新增一个轻量只读检查入口，复用项目语言和工具：
- 验证固定需求无遗漏、依赖顺序成立、verified 项证据真实存在且与代码身份匹配。
- 证据缺失、无测量分母、未执行项、过期证据、越权/版本违规、预算超限必须返回非零。
- 检查点/下一动作一致；失败关闭有前后证据；报告路径可访问。
- 检查不调用模型、不自动修改状态、不自行给自己业务批准。
- 机器检查只证明台账和证据一致，不能替代行为测试和人工业务批准。

同一功能关键路径变更后，相关旧证据标为需重验；不牵连无依赖模块。
不为满足记账频率重复运行全部测试，只运行与本轮变更匹配的必要检查。

## 10. 真实调用预算与避免无限循环

本节为建议执行配额：只有用户正式提交本文件作为执行任务后才适用，本轮编写不发生新调用。
用户启动消息可以覆盖本节；任务恢复时必须读取累计账本，不能重新获得整份额度。

建议整项新增真实 LLM 配额：
- 最多 800 次外部供应商请求，生成/规划/裁判/格式修复/自动重试全部计数。
- 最多 8,000,000 total token，以供应商 usage 为主；不同记账口径分别列出。
- 每轮最多 80 次；每一批先写计划请求数、输入/输出上限和剩余额度。
- 输出上限沿用已验证且符合服务能力的设置，不因预算默认降低导致推理未完成。
- 不充值、不购买模型、不新增付费 Embedding；没有计价依据不计算金额。

使用前核实脚本是否真正限制底层调用数，不把 1 次 HTTP 问答等同于 1 次模型调用。
先连通性/小批失败样本，再做同快照基线及候选 A/B；不要反复跑全量绿色套件。
调用前为输入和最大输出预留额度；usage 缺失时保存 unknown，按保守上界扣减，不能当 0。
无法得到安全 token 上界时暂停新增模型请求，继续无费用开发与测试，并报告剩余预算不确定。
额度不够完成全目标时停止相关调用，记录已完成/未完成与最小追加预算，不自动扩容。
历史批次的旧额度只属于原批次；新额度与旧调用分账，不重复使用已有 496 次评测配额。

每个失败循环必须增加证据或改变有依据的假设；同一故障反复无进展时停止盲重试，登记根因候选、阻塞和可独立推进项。
长命令采用日志文件和合理间隔检查，不高频空轮询。进程结束后采集退出码，不只看最后一行。

## 11. 证据和发布门禁

每个结论明确属于：
L1 静态；L2 SQLite/Mock；L3 真实组件；L4 真实模型；L5 浏览器/API 真实链路；L6 外部公网测试环境。
这些是不同维度的证据，不能仅用更大的等级编号替代缺失的另一种验收。

真实结果逐题保存：
case_id、run/attempt_id、代码/数据/索引/配置身份、候选/上下文/实际引用、主张-引文、权限/版本检查、答案状态/置信度/可信度、模型/裁判状态、延迟、token 和错误分类。
比率同时带样本数；unknown、未测、超时、预算耗尽和格式错误均不能记为支持或成功。
问题和黄金标签必须预先冻结；修正标注要另存版本、来源理由和前后差异，不按答案调预期。

门禁：
- 关键正确性和防误伤通过；权限越界/违规版本进入上下文为零。
- 调参/新留出分开，样本数和来源数明确。
- 同环境可比较基线的 Hit@5、MRR、引用支撑不降；p95 增幅不超过 20%。
- 不满足则保留实验开关和原默认，交付失败与阻塞。
- 当前代码的真实组件、真实模型、浏览器、远程部署和回退证据齐全。
- 仍缺人工业务批准时明确“不具备业务正式放行条件”，不冒充签字。
