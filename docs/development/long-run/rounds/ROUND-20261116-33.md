# Round 33：SQL 标识符 boost 与查询扩展开关解耦

日期：2026-11-16
阶段：P0-A 来源阻塞持续；P0-B 技术整改继续；P0-C/UX/远程目标未关闭；P1/P2 未放行。
性质：检索代码静态缺陷修复、隔离回归和本地真实组件 retrieval-only 对照；没有真实生成模型、judge、浏览器或远端调用。

## 发现与修复

- `HybridRetriever.search()` 原先仅在 `query_expansion_enabled=true` 时提取 SQL 标识符，即使独立实验开关 `retrieval_sql_identifier_boost_enabled=true` 也不会产生标识符信号。查询扩展开关会因此错误地同时关闭一个独立的 opt-in 精确正文匹配功能。
- 新增 `_query_sql_identifiers()`，只由 `retrieval_sql_identifier_boost_enabled` 控制抽取；调用点不再受 `query_expansion_enabled` 影响。
- boost 仍默认关闭；authority 排序、字段/表码信号、权限与版本过滤、拒答逻辑均未改变。未切换任何默认行为。
- 新增两个反例：扩展关闭但 SQL boost 开启时明确标识符仍提取；SQL boost 关闭时即使扩展开启也不提取。
- 实际组件回归采用 `backend/tests/rag_round33_project_replay.py`。脚本强制 `LLM_PROVIDER=mock`、查询扩展关闭，并在执行前锁定 dataset `10120bb...`、corpus `072efb...`、5985单元、index8/collection及无解析阻塞；任一身份不符即在查询前失败。
