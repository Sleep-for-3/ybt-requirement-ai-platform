# Round 61：智能体任务台状态信息与浏览器验收

日期：2026-11-18
目标：继续 `G-UX-AUDIT` / `G-UX-IMPLEMENT`，审查当前任务台真实布局与交互，并补齐非颜色状态线索。

## 审查结论

- 复核 Round20 已登记的空态入口、原生场景单选、目标草稿保留、短输入校验、移动端搜索和移除伪高级设置；当前代码仍保留这些契约，无需重复改造。
- 任务列表、结论及执行过程状态原先以中文文字和语义颜色呈现，但没有对应图标。对长列表和状态快速扫描而言，颜色是唯一非文本编码，且现有 UX 验收约定要求状态同时使用文字、图标和颜色。
- 任务台页头的流程说明“找到任务 → 看懂结论 → 查看依据或产出 → 完成下一步处理”属于使用说明，不是页面状态或业务数据；已移除，任务列表与标题仍表达页面实际工作对象。
- 桌面/移动截图中的页面整体保持紧凑的业务工作台结构；本轮不改变布局层级、状态语义、任务接口或证据授权。

## 实施

- 为共享 `ToneBadge` 增加 Lucide 语义图标：运行中使用旋转图标，完成使用勾选，失败使用告警，待处理使用时钟，信息与中性状态分别使用信息和空心圆标识。保留原中文标签和颜色；SVG 对辅助技术隐藏，徽标继续提供状态可访问名称。
- 在纯视图模型加入状态图标类型映射，并为运行、完成、待确认、失败和未知状态增加回归测试。
- 新增生产构建浏览器脚本，以合成 API 数据检查三种任务状态徽标均包含图标、流程说明文案不再显示，并验证 1440px 与 390px 页面无横向溢出。
