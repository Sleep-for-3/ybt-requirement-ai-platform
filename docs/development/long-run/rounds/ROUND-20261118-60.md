# Round 60：生成与引用裁判期间治理状态变化

日期：2026-11-18
目标：在真实隔离 PostgreSQL/Redis/Celery/Milvus 与本地 BGE 上，验证资料在答案生成或引用裁判等待期间撤回后，不会带着旧引用返回；并验证资料未变化时正常引用不受影响。

## 结果

- API源码身份匹配：通过。
- 受控服务/真实组件验收：4/4 通过。
- 正常路径防误伤：生成答案引用目标资料单元，资料未变化时正常返回。
- 生成中撤回：事务提交后最终引用复核拒绝答案，服务未返回旧答案。
- 引用裁判中撤回：judge 等待期间事务提交，裁判返回后最终引用复核拒绝答案，服务未返回旧答案。
- 外部 provider 请求/token 增量：0/0。Generator、judge、query planner 均为本进程受控 Mock；PG 与 Milvus/本地 Embedding 为真实隔离组件。
- 未发现需要修改业务逻辑的反例；仅新增隔离验收脚本。

## 证据边界

验收直接调用当前 `grounded_answer` 服务，并在两个 await 窗口用独立 PostgreSQL session 提交撤回；检索/治理/数据库交互为真实隔离组件。该轮没有通过运行中的 HTTP API 映射来验收异常状态码，也没有调用真实生成或裁判模型。合成资料不属于 gold/holdout；本结果只证明所覆盖服务路径在撤回后 fail-closed。

## 结论与限制

当前服务在生成前后以及引用裁判后均会重新验证资料权限、版本和生命周期；受控撤回在两个 await 窗口完成后，旧答案没有返回。无需为本轮反例修改业务代码。不能据此证明外部模型已收到内容后能被撤回，也不能替代真实模型、黄金集或 HTTP 错误呈现验收。
