# DSH 与 Codex 协作方案

日期：2026-09-30。用途：方案与迁移准备，不代表已经接通远程执行或启动监控。

## 结论与推荐

建议先在安装 dsh 的电脑上部署项目开发副本和具备本地项目访问能力的 ChatGPT/Codex 客户端，由 dsh 实现、Codex 分派有边界的任务并验收。先完成一个小工作包，证明能够读取代码差异、执行测试和返工，再逐步自动化。

用户已确认：dsh 为 DeepSeek Harness，目标电脑为 Windows。官方仓库已核实 headless、SDK、ACP 接口；具体安装版本、模型配置及目标电脑连接仍待核验。当前会话尚未连接该电脑或发送任务。安装普通聊天客户端、登录同一账号，不等于本会话已经能控制 dsh。具体落地步骤见 `Windows-DeepSeek-Harness执行方案-20260930.md`。

## 三种可行路径

| 路径 | 工作方式 | 适用条件 | 建议 |
| --- | --- | --- | --- |
| 同机协作 | dsh 实现，目标电脑上的 Codex 读取工作区、跑测试、给出返工指令 | 客户端有本地代码/终端权限；dsh 能接受任务 | 首选，最接近当前 Windows 环境 |
| Codex Cloud | 云端从 GitHub 当前代码分支创建隔离任务，实现或审查 | 私有仓库含最新未提交工作；完成云环境配置；账号显示可用入口 | 适合源码、单测和独立工作包；不直接接管本机 dsh |
| 自动调度桥接 | 调度端提交任务，dsh CLI/API 执行并回传状态/补丁/测试 | dsh 有稳定非交互接口和可恢复会话；受控文件目录/认证 | 第二步再做，接口确认前不写假命令或开放远程 shell |

官方云环境指南说明：通过 GitHub 仓库配置和发布环境，每个任务获得独立工作区；可以在本机休眠时继续执行。Plus 默认云任务资源为 2 vCPU、8 GiB 内存、8 GiB 磁盘。当前指南列出的限制包含 Computer and browser use；这不等于项目自带 headless Playwright 一定不可运行，必须在目标环境实际安装验证。此项目包含 FastEmbed、Milvus 客户端与浏览器依赖，建议先走 Mock/SQLite 测试，勿直接搬入全部缓存。[官方云环境指南](https://learn.chatgpt.com/docs/environments/cloud-environments)

官方 Remote 支持从手机指导已连接的 Mac/Windows 任务，需要连接授权且主机保持在线清醒；开放情况取决于客户端 rollout 和工作区设置。这与“让当前会话自动指挥任意第三方代理”是不同能力。[官方 Remote 说明](https://learn.chatgpt.com/docs/remote)

云端不是新增无限额度。任务的模型、上下文、复杂度和执行方式都会影响用量；不能承诺搬到云端后绕过 Plus 限额。[官方用量说明](https://learn.chatgpt.com/docs/pricing)

## 推荐的监督闭环

1. Codex 给出任务 ID、目标、修改范围、禁止事项、测试命令和通过标准。
2. dsh 先读取接手提示词并验证环境，然后只处理当前任务；不要同时启动两个写代理操作同一目录。
3. 每个可验收工作包输出：修改清单、代码 diff、测试命令/退出码/日志、未验证项、下一步。进行中也更新状态文件。
4. Codex 检查实际 diff，复跑关键测试；不能只认可 dsh 的“已完成”文字。
5. 不通过则提交具体返工项；通过后更新权威实施报告，继续下一个工作包。
6. 限额中断时写明最后已完成步骤、正在运行的进程、恢复命令和当前失败；恢复从记录继续，不从头重做。

最初可手工粘贴任务和返回结果；确认 dsh 非交互接口后再接自动调度。应提供只对该项目目录有效的接口，至少支持 submit、status、result、cancel 和幂等 task_id。禁止直接开放任意远程命令执行接口。

自动巡检要在连接、工作区和状态来源确定后配置。本次仅完成方案，不声称已启动长期监督，也没有新建云任务、上传仓库或发布环境。

## Git 与两台电脑的代码流

当前已完成的大量升级位于工作区的已修改/未跟踪文件，基线 HEAD 为 3e94e54。`git archive HEAD`、仅 `git diff`、只复制仓库远端，都不能独立覆盖完整工作区。

首次迁移以当前源码文件快照为准。之后建议用户选定一个私有仓库，把确认过的快照建立为新的交接基线；再分别使用实现分支与审查副本。推送、公开发布和部署须另行明确授权，本方案没有执行这些动作。若暂不用 Git，至少记录文件 SHA-256 清单并交换完整修改文件，不能依据旧基线对未跟踪文件做盲目补丁覆盖。

## 环境恢复与首次验收

当前宿主观察：Windows/PowerShell，Python 3.12.4、Node v24.15.0、npm 8.6.0。仓库 Dockerfile 为 Python 3.12 与 Node 20。不同组合均不能仅凭版本存在就宣布可复现；依赖和执行结果要在目标电脑确认。

前端按 package-lock.json 使用 npm ci。后端 requirements.txt 多数为范围版本，本次 inventory 是当前 Python 解释器实际安装版本的参考，不是依赖锁文件；不要复制 Windows .venv 到其他路径或操作系统。

首次先做隔离单测：

```powershell
# 在新电脑的 backend 目录；以下创建新虚拟环境，不拷贝旧 .venv
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DATABASE_URL='sqlite:///:memory:'
$env:ENVIRONMENT='development'
$env:TASK_QUEUE_PROVIDER='inline'
$env:LLM_PROVIDER='mock'
$env:EMBEDDING_PROVIDER='mock'
$env:VECTOR_STORE_PROVIDER='mock'
.\.venv\Scripts\python.exe -m pytest tests/test_field_candidate_vocabulary.py tests/test_ai_skill_field_candidates.py tests/test_ai_skill_candidate_preparation.py tests/test_retrieval_term_boundaries.py -q
.\.venv\Scripts\python.exe -m pytest tests/test_cross_layer_adoption_guards.py -q
```

```powershell
# frontend 目录
npm ci
node node_modules/typescript/bin/tsc --noEmit
# 需要浏览器验收时安装浏览器依赖
npx playwright install chromium
```

上述两组后端当前参考结果分别为 58 passed 和 12 passed。命令是目标机待执行步骤，本次没有重新安装依赖或在目标机验证。

如要恢复完整产品演示，先按 docs/ai-runtime/本地启动.md 配置新的本地密钥和空数据库。不要直接运行旧“项目启停.ps1”连接用户业务库；它的默认生产启动路径会涉及 PostgreSQL/Milvus 和迁移。云端/Linux 需把 PowerShell 环境变量写法转换为 shell export，并采用新隔离数据库；这份文档不是未经测试的云安装脚本。
