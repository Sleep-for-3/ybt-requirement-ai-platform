## 本轮新增修复

### 1. 项目创建与重复提交

项目创建失败但实际已写入的问题来自浏览器端 React 事件时序，不是 PostgreSQL 或 WSL 数据库差异：

- 请求成功后再次读取 `event.currentTarget`，此时 React 已清空该引用，随后调用 `reset()` 触发前端异常。
- 用户看到失败并重试，数据库因此出现重复项目。
- 修复为请求前保存表单引用，并使用稳定的 `client_request_id` 做幂等创建。
- PostgreSQL 唯一约束负责并发场景的最终兜底。

### 2. 项目生命周期

项目不做物理删除。项目是权限、资产、血缘、脚本、需求、审核、UAT、交付和审计记录的隔离边界，硬删除会破坏历史引用和追溯链。

当前生命周期为：

- `active`：正常选用、进入工作台和初始化。
- `suspended`：从常规项目选择中隐藏，保留全部历史。
- `active` 恢复：直接恢复原项目，不复制、不重写历史。

产品上应继续使用“停用项目”和“恢复项目”，不要向用户提供“彻底删除项目”。如未来必须支持合规删除，应另建受审计的归档/销毁流程，而不是普通删除按钮。

### 3. 脚本重复导入后的资产重绑定

生产验收发现：脚本先解析、后导入 DDL/Excel 元数据时，再次导入相同脚本会命中原版本并直接返回，旧血缘节点没有重新绑定新目录资产。结果是字段路径提示“缺少上游字段元数据”。

修复后，重复导入只重跑保守资产解析，不创建重复脚本版本，也不执行上传脚本。脚本中的库、Schema、表、字段会与当前项目目录重新匹配；只有唯一候选才自动绑定，歧义仍交给人工确认。

### 4. 历史脚本版本回导

进一步修复了历史版本回导语义：

- 如果重复内容就是当前版本，保持现有幂等行为。
- 如果回导的是历史版本，该不可变版本重新成为当前版本，但历史版本行全部保留。
- 后续新版本号按数据库中的最大版本号继续递增，不会与历史版本冲突。
- 变更对比的基线使用回导后的当前版本，不拿错误的新版本作为基线。

这解决了“界面提示导入成功，但当前脚本实际仍是另一份内容”的版本歧义。

### 5. 模型输入预算与失败分类

- 模型 Profile 增加 `requirement_max_input_bytes`，旧配置未设置时使用安全默认值 `64000`。
- `403/409/422` 分别归类为权限、输入冲突、校验阻断，不再全部伪装成策略阻断。
- 真实模型连接测试返回 HTTP `200`，模型为 `openai_compatible/deepseek-chat`。

## 产品体验优化建议

### P0：送审前缺口向导

当前生成完成后，用户会看到“生成成功”但 readiness 仍有 6 个阻断。建议把阻断按制度对照、业务定义、字段映射、证据四类分组，并在每项旁提供直接跳转和负责人建议。首页工作流应明确显示“生成完成 → 人工确认 → 可送审 → 审核 → 正式交付”。

### P0：制度对照的人工作业效率

模型已能生成候选对照，但逐条人工采用、冲突确认和规则关联仍较慢。建议增加批量采用、仅看差异、按条款分组、键盘快捷确认和“无依据”显式标记。任何批量操作仍应保留逐条审计。

### P1：项目生命周期解释

“停用项目”按钮旁应持续显示“历史资产、需求、审核、交付和审计记录会保留”。停用确认框应说明恢复路径和不会释放项目名称。这样用户不会把停用误解为失败，也不会寻找不存在的彻底删除。

### P1：重复项目治理

旧前端缺陷留下的疑似重复项目应保持停用状态，不做物理删除。建议增加管理员视图，按项目名、机构、资产数、需求数和交付数对重复项分组，只允许停用确认过的空项目，并保留操作审计。

### P1：版本变化影响摘要

脚本、DDL、Excel、监管模板或制度版本变化后，现有待复核提示只有变化列表。建议增加影响摘要，包括受影响需求数、字段数、是否已正式交付、建议动作和变化证据。用户显式建立新修订后，旧版本继续保持不可变。

### P1：错误恢复信息

同类接口冲突目前常返回“资源状态冲突”。建议返回冲突资源、当前版本、请求版本、已有任务或幂等记录，并给出可执行的恢复动作。对模型 JSON 失败，错误日志应保留脱敏后的解析失败位置和响应长度，不记录完整敏感上下文。

### P2：前端性能与静态资源

- 验收中 `/api/auth/me` 偶发约 1.4 秒，建议对重复鉴权请求做短时缓存或请求合并。
- Next.js 页面预取请求较多，建议检查导航预取策略，避免同时加载大量不可见页面资源。
- `favicon.ico` 当前返回 404。补齐品牌图标可消除浏览器控制台唯一剩余噪声。

### P2：导出可验证性

建议在 Word 首页和 Excel 固定版本表中直接展示需求版本、快照 ID、快照哈希和导出时间，便于业务、审计和测试在不查看响应头的情况下核对同一版本。

已验证：

- 项目创建幂等和停用/恢复。
- 重复脚本导入后的目录资产重绑定。
- 历史脚本版本回导和单调版本分配。
- SQL、DDL、Excel、ZIP 的确定性导入与失败重试。
- 来源直接到监管目标的路径确认、审核就绪和固定导出。
- 真实模型两章节生成成功。
- 脚本变更只提示待复核，历史快照和固定导出不变。
- 生产浏览器核心页面、Word/Excel 下载和 11 项健康检查。

未验证：

- 生产环境低权限账号的完整浏览器 RBAC 验收。
- 生产环境多层数仓项目的真实浏览器全流程。直接路径为生产实跑，多层层级路径由确定性自动化测试覆盖。
- 多目标监管表在同一批次的真实模型生产验收。
- 正式审核、正式交付和 UAT 全流程生产浏览器验收。
- 真实银行数据查询。首版明确不执行真实银行数据查询。

遗留风险：

- 一个字段的业务定义和制度逐条对照仍需要业务人员完成，系统不能代替人工确认。
- 模型输出偶尔可能不满足严格 JSON Schema。现有结构校验会阻断错误输出，但不能保证外部模型永久稳定。
- 生产磁盘空间健康，但服务器仍需持续监控 Docker 镜像、日志和备份增长。
