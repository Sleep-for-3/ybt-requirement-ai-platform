# 智能体任务台：纯问答的三处体验问题（2026-11-05）

线上反馈：在智能体任务台提交一个纯问答（"互联网贷款协议表都有哪些主要字段"），
界面一直显示"正在提交"、任务却在后台跑；跑完还要求"批准并继续"；批准后又只回
一句"现有知识库没有足够证据"。

## 根因与修复

### 1. 创建任务被模型规划阻塞（"一直显示正在提交"）

`POST /api/projects/{id}/agent/tasks` 在请求内同步跑 `plan_with_llm`，一次模型调用
十几秒到一分多钟，前端 60 秒 abort，任务其实已经入队。

- `runtime.create_task(..., defer_llm_plan=True)`：请求内只落确定性计划，把
  `result_summary.planner_pending = "llm"` 留给后台作业；`_finish_deferred_planning`
  在 `_run_task` 里先做模型规划再执行。
- 接口返回 202，实测 0.4~1.2 秒返回。

### 2. 纯问答要走人工批准

问答被路由到 `regulatory_field_analysis`，解析不出唯一分析对象就弹
`clarify_subject` 网关，后续 5 个只读步骤又都 `requires_human_confirmation=True`。

- 新增场景 `knowledge_question`（有哪些 / 是什么 / 如何 / 多少 / 列出 / 查询 / 解释），
  `requires_subject=False`，确定性计划 `search_metadata → answer_knowledge_question`。
- 注册表不变式：`requires_human_confirmation=True` 必须是 high/critical 风险；
  只读工具一律不开网关（`compare_policy_and_implementation`、`compare_sql_versions`
  同步改为 medium / 不拦截）。
- 问答任务 `adaptive=False`（没有可修订的写操作计划）。
- 前端：`knowledge_question` 任务不再渲染"分析对象（主体解析）"面板。

### 3. 答案是空壳（"现有知识库没有足够证据"）

三个原因叠在一起：

1. `search_metadata` 拿整句（"……都有哪些主要字段"）去做 `search_catalog` 和
   `ilike`，表名/字段名永远匹配不上；命中表名时也没有把该表字段带回。
2. 项目里存在"互联网贷款合作机构信息表"这类中文表注释，但 `search_catalog` 的排序
   按整句相似度算，问物理表名（`hyf_ln_pa_online_info`）时目标表会被别的表挤到 top_k 外。
3. 模型规划有时只排一步 `answer_knowledge_question`，工具读不到任何目录行。

修复（都在 `app/services/agent/tools/builtin.py`）：

- `search_metadata`：先用原句、再用 `_question_core_terms()` 截出的核心词各检索一轮，
  按 id 去重；对问句里的英文标识符先做一次 `CatalogTable.table_name` 精确查询
  （必须在相似度检索**之前**，否则被 top_k 提前填满就跳过）；命中表名后把该表
  字段一并带回（`source_table`/`mart_table` 展开成字段行）。
- `answer_knowledge_question`：只要没有引用支撑而目录有命中，就用目录事实作答，
  `answer_status="metadata_only"`，回答里给主表（带中文注释）的字段清单与物理变体表；
  没有前置检索步骤时工具自己补一次目录检索，并为这些列补 `catalog_field` 证据。
- 前端问答结果面板三态：`grounded`＝有引用支撑、`metadata_only`＝依据元数据目录
  （未引用监管文档）、其余＝证据有限。

## 验证

- 后端：`pytest tests -k "agent"` → 232 passed，1 个预存在失败
  （`test_ai_intelligence_benchmark.py::test_dim_g_agent_self_correction_loop`）。
  `tests/test_agent_knowledge_question.py` 9 条用例覆盖：场景路由、只读无网关、
  创建不跑模型、后端规划完成、核心词回退、物理表名精确命中、metadata_only 作答。
- 生产（项目 33）：
  - `互联网贷款合作机构信息表都有哪些字段` → 2 步/1 步计划都能答出
    `hyf_ln_pa_online_info` 的字段清单，`metadata_only`，0 个 `waiting_human`。
  - `hyf_ln_pa_online_info 表有哪些字段` → 命中该表 20 个字段（不再答成
    `hyf_cd_info`）。
  - `互联网贷款协议表都有哪些主要字段` → 该项目目录里没有这张表（只有
    "信贷借据互联网贷款补充信息表""互联网贷款合作机构信息表"），仍如实回
    "证据有限"，但不弹批准、不阻塞。

## 部署

镜像 `uxfix21`（前端问答面板）→ `uxfix23/24/25`（后端检索与作答），
`docker compose -p source -f docker-compose.yml -f docker-compose.server.yml`，
构建走阿里云 pypi / npmmirror 源。

## 已知遗留

- 线上旧任务 #2 仍是历史 `waiting_human` 记录（改造前创建的），可在页面"取消任务"。
- `search_catalog` 本身仍按整句相似度打分，后续可考虑改为"表名/注释命中优先 +
  问法词剔除"，本轮只在工具层做了排序与精确兜底。
