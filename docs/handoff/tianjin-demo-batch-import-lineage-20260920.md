## 4. 发现的问题与修复

### 4.1 前台没有菜单入口

现象：生产原先运行旧版本，侧边栏没有新增页面入口。

修复：在现有导航契约中增加“数据架构与表归属”和“统一批量导入”，随 `ea13b5b` 发布。

### 4.2 SQL 先于 DDL 应用时节点未绑定目录

现象：批次内 SQL 已解析，但后续 DDL 才创建目录表，血缘节点仍为空目录绑定。

修复：批次全部文件应用完成后，统一对批次内所有脚本版本执行 `reresolve_lineage_version`，再构建 revision。旧 revision 保留，不覆盖历史事实。

### 4.3 应用结果仍显示导入前“缺少唯一目录资产”

现象：应用后 `preview_json` 仍保留应用前的匹配结果，页面显示过时警告。

修复：在目录、脚本和血缘绑定完成后重新计算 `batch.preview_json`，使结果页展示当前已落库的目录绑定和层级。

### 4.4 DDL 小写标识符与 SQL 大写引用无法匹配

现象：DDL 解析出 `ods_hrm_l_p_k01`，SQL 引用为 `ODS_HRM_L_P_K01`，旧逻辑按精确大小写匹配，导致 19 个引用全部显示缺少目录资产。

修复：物理身份匹配改为“先精确匹配，再仅在 database、schema、table 三段均不区分大小写且结果唯一时回退”。该规则不会把同名不同库或不同 Schema 的表合并。

### 4.5 历史后台任务残留 running

现象：job 181/182 状态长期为 `running`，队列实际为空。

修复：job 181 标记为 `failed`，说明被同一幂等请求的后续预览版本取代；job 182 标记为 `completed`，写入批次 17 的真实成功结果、脚本版本和 revision 10。

### 4.6 PostgreSQL/WSL 问题判断

本次问题不是 PostgreSQL 版本或 WSL 独有缺陷，而是应用层的物理身份匹配和批次预览刷新问题。因此：

- 使用 WSL 中的 PostgreSQL 运行同一旧代码，也会遇到相同结果。
- 修复后的逻辑不依赖数据库大小写排序规则，PostgreSQL 和本地隔离数据库测试均通过。
- 生产使用 Docker 中的 PostgreSQL 16；没有执行数据库重建，也没有覆盖已有数据。
