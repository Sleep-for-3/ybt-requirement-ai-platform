# 本地启动说明

`backend/.env.example` 是公开模板，Docker Compose 实际只读取未纳入 Git 的 `backend/.env`。复制模板后必须人工检查配置；项目不会自动复制模板，也不会把 Secret 烘焙进镜像。

## Windows 本地一键启停

已准备 `backend/.venv` 和 `frontend/node_modules` 时，可以直接右键 `scripts/项目启停.ps1`，选择“使用 PowerShell 运行”。无参数启动会进入常驻操作菜单：

- 进入窗口立即显示项目是否完整运行；
- 显示前端、后端、PostgreSQL、Redis、Celery Worker、Milvus 和 FastEmbed 的存活状态及 PID；
- 显示前端、接口文档、健康检查、数据库和 Redis 地址；
- 操作失败时显示错误原因及最近错误日志；
- 必须选择“退出窗口”才会关闭；退出窗口不会停止项目。

在已有 PowerShell 中也可以使用下面的非交互命令：

```powershell
.\scripts\项目启停.ps1 start
.\scripts\项目启停.ps1 status
.\scripts\项目启停.ps1 restart
.\scripts\项目启停.ps1 stop
```

脚本默认使用 `production` 模式，依次启动本机 PostgreSQL、Redis、WSL/Windows Docker 中的 Milvus、FastEmbed、Celery Worker、FastAPI 和 Next.js，执行 Alembic 并等待健康检查。PostgreSQL 与 Redis 的可执行文件需已安装且能被 PATH 或 Scoop 发现；Celery 使用 `backend/.venv` 中的依赖，并在 Windows 使用 `solo` 进程池。

没有在 `backend/.env` 显式配置非 Mock Embedding 时，脚本使用本地 `BAAI/bge-small-zh-v1.5`，维度为 512，模型缓存位于 `.local-run/fastembed-cache/`。首次启动约下载 90 MB，并实际生成一个向量完成自检；端口存在但模型不能推理时不会误报为完整运行。

日志、进程状态及仅供本机使用的随机数据库密码和 `pgpass` 文件保存在已被 Git 忽略的 `.local-run/`；数据库 URL 不包含密码。后端端口优先从 `frontend/.env.local` 的 `NEXT_PUBLIC_API_BASE_URL` 读取，未配置时使用 8000。

首次启用 production 模式时，脚本只会把指定的 SQLite 历史库迁入“本次启动刚创建”的 PostgreSQL 专用空库。复制和序列重置在一个事务内完成，成功后才写入 `.local-run/sqlite-migration-complete-*.json`；如果迁移中断，PostgreSQL 会回滚到迁移前状态。任何启动前已经存在、但缺少完整迁移标记的数据库都不会被自动覆盖；脚本会列出非种子业务表并要求先备份、手工核验：

```powershell
.\scripts\项目启停.ps1 start -Mode production -DatabaseFile local_main_test.db
```

仅在临时调试或没有 PostgreSQL/Redis 的机器上使用 SQLite 兼容模式。该模式以内联方式执行任务，大文件索引会占用 API 请求进程，不适合作为日常运行方案：

```powershell
.\scripts\项目启停.ps1 start -Mode sqlite -DatabaseFile local_development.db
```

知识文件上传在 production 模式下会立即返回 `202 Accepted` 和后台任务编号。页面按任务进度轮询；Worker 按 `KNOWLEDGE_INGESTION_BATCH_SIZE` 分批写入知识单元、关键词、实体关联、嵌入记录和向量记录。

production 模式固定使用共享 Milvus，并保留 `etcd_data`、`milvus_minio_data`、`milvus_data` 三个 named volume。停止脚本只停止容器，不执行 `down -v`。首次建立 active 索引前，`semantic_index=degraded` 不阻止后端启动；索引验证并原子激活后应显示 `healthy`。

## Windows PowerShell

```powershell
git checkout main
git pull origin main
cd <仓库目录>
Copy-Item backend/.env.example backend/.env
notepad backend/.env
python scripts/check_local_setup.py
docker compose up --build
```

## Linux / macOS

```bash
git checkout main
git pull origin main
cd <仓库目录>
cp backend/.env.example backend/.env
${EDITOR:-vi} backend/.env
python scripts/check_local_setup.py
docker compose up --build
```

## Windows 上 Docker 仅安装在 WSL 时

如果 PowerShell 提示找不到 `docker`，但 `wsl docker version` 能正常返回 Server 信息，`项目启停.ps1` 会自动使用 WSL Ubuntu 中的 Docker，并在项目运行期间保持该发行版存活。也可以先在 PowerShell 中确认：

```powershell
wsl docker version
wsl docker compose version
```

Docker Hub 直连不稳定时，可只为 WSL Docker daemon 配置 Clash HTTP 代理。当前机器的 Clash Verge mixed-port 为 `7897`，systemd drop-in 位于 `/etc/systemd/system/docker.service.d/http-proxy.conf`。修改后执行 `systemctl daemon-reload` 与 `systemctl restart docker`，再用 `docker info` 核对 HTTP/HTTPS Proxy；不要在仓库中保存订阅、节点或认证信息。

检查脚本输出 `PASS`、`WARN` 和 `FAIL`，不会打印 API Key。存在 `FAIL` 时退出码为 1；只有警告时仍为 0。

启动后访问：

- 前端：<http://localhost:3000>
- 存活检查：<http://localhost:8000/health/live>
- 就绪检查：<http://localhost:8000/health/ready>
- OpenAPI：<http://localhost:8000/docs>
- AI 运行环境：<http://localhost:3000/model-profiles>

`/health/ready` 只验证 Provider 配置完整性，不发起收费模型请求。联网测试必须由管理员在 AI 运行环境页面点击“测试连接”，或显式运行：

```powershell
python scripts/test_llm_connection.py
python scripts/test_llm_connection.py --embedding
```

这些命令只发送固定的最小连接测试文本，不读取项目、知识库、银行文件或用户输入。
